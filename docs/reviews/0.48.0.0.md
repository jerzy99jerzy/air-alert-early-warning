# Review 0.48.0.0: fifteen areas nothing would ever correct

Version: 1.0 / 2026-08-31

The release exists because the map was rendering calm over measured alarms and
the population could only grow. `[measured]` means executed in this
repository's container against the 0.47.0.0 tree or read from the 2026-08-30
production dry-run; `[inference]` is argued from code reads.

## 1. The mechanism was one, in three layers, and the repair had to be too

Source keyed per `(area_id, kind)`, identity excluded `kind`, fold collapsed
per area. Each layer was individually defensible and the three together made
the clear of one threat kind erase the area (F133). The repair aligns all
three - fold (D-044.1), write path (D-044.2), census (D-044.3), identity
(D-045) - and the release ships them together because each "ships alone" row
in the D-044 table was checked and each fails differently.

## 2. Controlled, not just green

The new tests were run against the unpatched 0.47.0.0 tree first. Both
measured populations assert empty there (`assert [] == ['UA12']`) and stand
after the patch; the single-kind case is byte-identical either way. A suite
that has never been observed failing is not evidence, and this one was
observed failing in the right direction before it passed.

## 3. Two defects the session put in and took out, recorded on equal footing

- **Class 3.** The first draft ran re-dating on both collectors, from the
  claim that the invariant was a property of the log. False: a snapshot
  assertion means "standing now", a log assertion means "a message existed at
  T", and `test_sprint11` measured the consequence - a repeated poll grew the
  log and resurrected an ended alert. The boundary is now stated in the
  docstring and pinned by its own test.
- **Ordering.** `sorted()` over `(str, ThreatKind)` raised the moment two keys
  shared an area, because Enums are unordered. Every unit test had one kind
  per area; the end-to-end run on the 2026-08-30 shape found it. Regression
  test added, and the lesson is the fixture rule again: choose fixtures
  against the channel's shape, not the implementation's.

## 4. The identity change is the finding

D-045 began as an unblock for `--unmask` and ended as the causal account of
the thirteen: the D-042 re-key emitted their activations under the new kind,
the old hash discarded them as duplicates of the pre-re-key rows, and the
store refused the very rows whose absence it then rendered as calm
`[inference, mechanical]`. The migration argument - expected duplicate count
zero on the production store - rests on two measured properties: a key in
`previous` never re-emits, and the channel cursor reads forward of a publisher
that stopped on 2026-08-29.

## 5. What this release does not claim

The trailing seven-day layer still pairs episodes as it did; its behaviour
under multi-kind interleaving is `[unverified]` and was not touched. F135 and
F136 stay open and E-0 stays blocked behind F136. The gate here ran on Python
3.12 only; the tag waits for CI green per interpreter, per job, as always.

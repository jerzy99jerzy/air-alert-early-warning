# Review 0.50.0.0: the gates were counted, and one of them was counting nothing

Version: 1.0 / 2026-08-31

Opened on a judgement rather than a defect report: that the project had put too
many gates on itself and the documents had drifted. Both halves were measured
before either was acted on, and the measurement changed the shape of the answer.

## 1. The gate burden, measured in both directions

Sixteen checks run in `verify`. On the day this review was written they caught
three real defects: a `str_replace` that silently matched nothing and left two
document headers unbumped, a deployment row disagreeing with its own pin after
a version change, and a test stub missing a field the code had grown. That is
not a gate to remove.

Four mechanisms, however, were costing time without catching anything, and all
four had the same shape: **a figure living in two places with a check
comparing them**, rather than living in one place and being generated. The
worst was a fixed point - `README.md` sits inside the `documentation` group
whose line count `README.md` prints - which made convergence a two-pass
manual dance every release. `precision_lint` read document version strings as
false-precision measurements and fired three times in one session. Six badge
figures were synced by hand.

## 2. What the counting found: F139

`Releases | 44 in the changelog`, against a changelog holding **122**. Wrong by
78. Three figures beside it in the same table claim the same provenance and are
all correct, so the row read as trustworthy by association.

The mechanism deserves stating plainly because it is not carelessness.
`defects_logged` and `decisions_recorded` are pinned and compared; `releases`
was pinned nowhere, and what maintained it was ceremony - each release
incremented it by one. That produces a number recently *touched* and never
*checked*. Three of those increments happened in one session, by the author of
this review, none preceded by a count.

**Sixteen checks could not have caught it**, because every one of them compares
a document against a pin, and a figure with no pin is outside the guarded set.
This is the project's own standing lesson arriving from a new direction: a rule
without a gate check is a preference, and here, a figure without a pin is a
rumour.

## 3. The repair, and its boundary

`tools/figures.py` (D-046) computes every figure the tree can recompute from
itself and writes it to both places that hold it; the gate checks the
regeneration. The pattern is `todo_index.py`'s, which has never drifted. The
fixed-point loop moved inside the tool, where it runs once.

The boundary is the decision, and it was broken and repaired inside this
release. A figure a person measured - corpus counts, host readings, latency
distributions - is not derivable and stays pinned with its provenance. Nor is
the test count or the coverage percentage: those describe a run, and
`make verify` writes them in the same pass that later checks them, so a
generator reading them reports drift on every run that touches a test. The
first implementation did exactly that, which would have reinstated the manual
dance this release exists to remove, one directory over. Caught by running the
gate rather than by reasoning about it. `docs_audit` keeps those pins.

The generator also refuses to write a zero when an artefact is absent, because
a zero in a pin is a measurement claim nobody made.

## 4. Documents: the drift was narrower and worse than the grep suggested

A count of `telegram` per document overstated the debt: most hits are
references to `mavo/sources/telegram.py`, a file that still exists and still
runs as the watchman. Two claims were actually false, and one of them sat in
the threat model: *"the API adapters do not exist yet"*, written while
`ukrainealarm_source.py` had been the primary source for a day.

The real cost was elsewhere. **BRIEF and BRIEF-PL** - the two documents an
outside reader reaches, and the ones sent outward - were pinned at 0.32.9.0,
seventeen releases back, and told that reader the project reads one public
Telegram channel. Both now carry the outage, the switch, the watchman role, why
two feeds are not two sources, and the named cost of the switch. The corpus
figures did not move and are said not to have moved.

## 5. S9, and what reading it turned up

S9's exit criterion is one row in `docs/CHANNEL.md` 8a. Its entry said the row
waited on T66; T66 closed at 0.41.0.0, nine releases earlier. Underneath that
discharged blocker sat the real one: `tools/latency.py` reads the event store
from `tools/`, which the wheel does not ship, so it has never been runnable on
the machine holding a store. **That is D-038, applied to `attempts.py` and not
to its class** - filed as T84 rather than patched here, because the repair is a
package move plus a check that enumerates the class, not an edit.

## 6. Errors of this session

The `releases` increments described above, twice, by this author. A generator
whose first version reordered `STATUS.json` keys and invented a synonym key
beside an existing one, both caught by reading the diff rather than by any
check. A regex written to match `Version: 1.16` that omitted the colon, caught
by its own assertion. The pattern across all of them is the one this review is
about: writing a rule from the shape a thing is assumed to have, rather than
from the shape it has on disk.

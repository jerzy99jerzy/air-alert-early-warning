# Review, 0.38.0.0

Version: 1.0 / 2026-08-22

The release that read the endpoint instead of its documentation, and found the
documentation wrong in three places and this repository wrong in two.

## What shipped

`mavo rso` polls the Polish civil-warning feed, walks all five published
categories, stores communiques in a table of their own keyed on content digest,
and logs every attempt whether or not it succeeded. Nothing renders; nothing
reaches the contract. The reader now has a caller and a store, which is what
T67 asked for short of a live fetch from the production host.

## What the reading corrected

**Four beliefs held before this session, all of them from documentation.**

| Believed | Measured |
| --- | --- |
| `wszystkie` returns the feed | 156 of 461; `stany-wod` omitted silently |
| `totalItems` is a total | items on the requested page |
| The feed never carries RCB | it has since April 2024, indistinguishably (date corrected at 0.38.0.1, F112) |
| The feed holds current state only | records reach back to 2026-01-28 |

The last two matter beyond this release. The docstring's claim about RCB was
written from a correct fact about the statutory SMS and generalised to an
institution; the correction is in `mavo/sources/rso.py` and in T67.

## What did not ship, and why

**No emission to the contract and nothing on the page.** The naming question is
unresolved and it is not a rendering detail: communiques from the government
centre and from sixteen voivodeship crisis centres arrive with no field
distinguishing them, so any single heading is wrong about part of the block.
That belongs to the consumer's release and to the operator.

**No live fetch from `vm-mavo`.** The host is IPv6-only in practice and every
Polish state source measured publishes `A` records and no `AAAA`. This is the
consumer's own network, correctly configured for the sources it was built to
reach, and it is recorded in FEED-SPEC sixteen rather than as a defect against
anyone.

**No `stany-wod` decision.** 305 of 461 records, all bearing today's date,
which is a sensor reading overwritten in place rather than an event. A store
keyed on content digest would grow by 305 rows a day in perpetuity. D-034
forbids dropping by category and stands; whether this category is the same
stream at all is a question for the operator and is open.

## The instrument problem

F111 records five counters read as measurements of something they did not
measure, in one evening, by the assistant. One of them had a conclusion drafted
for a public document naming a broadcaster and a ministry before a control
measurement overturned it. The control was requested by the operator.

The rule that comes out of it is in F111 and is worth repeating here because
reviews are where it will be checked: a counter without a falsifying case
beside it is not a measurement.

## Open, in order

1. The naming decision, which blocks the consumer's release.
2. `stany-wod`: one stream or two.
3. A live fetch, which needs either egress or a file carried by hand. The data
   is history rather than a stream, so carrying a file is not a workaround.
4. CAP behind a token: the only interface found that carries issuer and
   category, and reaching it is an outreach action rather than a technical one.

Version: 1.0 / 2026-09-10

Mandated as "I do not understand why sprint S9 is still not finished, carry on
with the next backlog items, let us finally close the producer", against the
0.53.5.1 producer tree as uploaded on 2026-09-10. `[measured]` means executed
in the container this session, on CPython 3.12.3; `[reported]` means taken from
a document in the tree and not re-measured here. No host was reached this
session and nothing below is a reading of production.

## 2. The question, answered against the tree rather than the handover

**S9 was open for three reasons and only one of them was work.**

*The criterion and the sprint board are different objects.* D-032 gives S9
three clauses; `TODO.md` assigned four tasks to it. Only T40 touches a clause.
T39, T37 and T47 were parked there when S8 closed at 0.32.9.0 and were never
part of what the sprint had to prove, so the sprint read as unfinished partly
because of bookkeeping `[measured, docs/MVP.md and TODO.md]`.

*T40 was blocked by something no document named until 0.50.0.0.* The stated
blocker, T66, closed at 0.41.0.0. The real one was that `tools/latency.py`
reads the store and `tools/` is not installed by the wheel, so the instrument
had never been runnable on the only machine that holds its input - D-038
applied to one file rather than to its class.

*The figure the entry claimed to hold does not exist in the tree.* T40 says
"distribution taken 2026-08-19"; the README says the distribution is taken and
8a is empty on purpose for a third reason, an unattributed term in the tail.
No median, p90, p99 or maximum appears anywhere under `docs/`, in the changelog
or in `STATUS.json` `[measured, grep across the tree]`. Whatever was taken was
not written down, and three documents give three different accounts of why the
row is missing. That divergence is the finding, not the missing row.

## 3. The instrument, run for the first time against a store the package writes

This is the part that changes what the release is.

A store was built with `EventStore`, nine rows in `events` and nine in
`kind_events`, and the instrument was run against it. It reported **nine
observations** `[measured]`. It reads `events` and `kinds`; `mavo/store.py`
has never created a table called `kinds`, and the miss sat under
`except sqlite3.OperationalError: continue` commented as backwards
compatibility. F154.

Eleven regressions had guarded this file since 0.30.0.0 and none could see it,
because `tests/test_latency.py` created a table with the name the module used.
Test data chosen by the implementation rather than against it - the class this
repository has logged four times, and the fourth instance is the one that hid a
defect for twenty-four releases.

Reading further, the same instrument pooled every row in the store into one
distribution. That was correct while one feed existed. The store now holds the
channel era and the API era, and on the API path an all-clear carries
`ts_source = ts_ingest` by construction, because the source never says when an
alert ended `[measured, mavo/sources/ukrainealarm_source.py]`. One median over
that mixture names none of its three populations and carries a spike of
constructed zeroes under every percentile. F155, and the same source-dimension
blindness `compose()` carried until 0.53.0.0, one layer out.

**The conclusion the release is built on.** A row written into
`docs/CHANNEL.md` 8a at any point in the last twenty-four releases would have
been wrong twice, would have looked like a measurement, and would have closed a
sprint. The clause is withdrawn under D-051 rather than met, and 8a stays
empty.

## 6. Residual risk

The gate now enforces D-038 across `tools/`, but it reads imports and
connection calls from the syntax tree: a store reached through a subprocess or
over SSH is invisible to it, and that limit is written into the check rather
than left for a reader to discover.

The `constructed_stamps` discriminator is exact timestamp equality. On the
channel path, where the source clock has second resolution and ingest has
microseconds, a genuine zero-lag row is implausible; if a future source stamps
at the same resolution as this collector, real observations would be held out
of the distribution and counted as constructed. The count is printed beside the
figures for exactly that reason.

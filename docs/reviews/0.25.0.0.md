# Review, 0.25.0.0

Carried out on 2026-08-12, against the release that gave the contract a
history. D-021 asks for this on a major release.

**This release cannot be deployed by itself, and that is the first thing a
reader needs to know.** The v3 payload is a strict superset of v2, but
`mavo-site` 3.0.0.0 refuses any version it does not recognise, deliberately,
because a page rendering an unfamiliar payload with familiar assumptions is
worse than one that says it cannot read the file. Shipping this to production
without the site release turns the page blind: correctly, and uselessly.

## What the number 200 was, and what it should have been

The first draft of D-024 capped the stream at 200 events, justified by "MAVO
sees about a dozen transitions a day". The operator said the cap looked low.
He was right, and the reason was worse than a low estimate.

That dozen described **western** areas. The stream carries **all** of Ukraine.
One number, two denominators, which is exactly T49's shape, logged four days
ago and repeated here by the person who logged it.

The measurements that settled it:

| Quantity | Value | Provenance |
| --- | --- | --- |
| Store growth on the production host | 27 events in 97 minutes, about 400/day | measured, one window |
| Events per parsed message | 1.72 | measured, one live poll |
| Posts per day | 514 | measured, corpus |
| Estimated events per day, all Ukraine | ~800 | inference, chained |
| Western share | 3.5% of tag occurrences, ~28/day | inference from a measured share |

A 200-event cap would have bound on every single day, which makes `truncated`
permanently true and therefore worthless as a signal. The failure would not
have been visible as a failure: the panel would have shown a plausible feed,
truncated silently at a boundary nobody chose deliberately.

## The argument that was wrong, and how it was wrong

The second draft kept the cap low by filtering the stream to the west, on a
bandwidth argument. The operator rejected the framing and asked for the east.

Recomputed in seconds rather than in percentages, the argument was weak: a full
day of all-Ukraine events is about 18 KiB gzipped, or 1.2 seconds on the
120 kbit/s line this project designs for. Presenting that as "more than doubles
the recurring traffic" was true and irrelevant. The relative figure was doing
rhetorical work the absolute figure would not support.

Where the argument survives is at the tail: a campaign night at 2,000 events
is 3 seconds, **every two minutes**, which is not nothing. That is why the
answer is two files rather than a filter. Full visibility, paid for once when
the reader asks for history.

## What is not in this release

**A deprecation policy for v2**, which T50's acceptance asks for by name. This
project has one consumer and controls it, so the absence is survivable today
and stops being survivable the moment anyone else reads the contract.
FEED-SPEC section 3 property four is exactly this obligation, written for
somebody else's feed and now owed by ours.

**A size measurement under a mass alert.** Every figure above rests on quiet
nights and on one 97-minute window. The case that breaks a feed is the case
that has not been measured, and it will not be measured until a campaign night
lands while the collector is running.

## A field this release deliberately did not touch

`shipped_sprints` still reads 0 to 9 while `tests/test_sprint10.py`,
`test_sprint11.py` and now `test_sprint12.py` exist. F93 established that the
field means "a test file exists", so by its own definition the value is wrong.
Adding 12 made the gate report a hole, which is the gate working.

Correcting the value would assert that sprints 10 to 12 shipped, which is a
larger claim than the field can support and than the README makes. The field
needs the rename F93 implied rather than an edit, so it stays wrong and stays
named here. A wrong value that is documented is cheaper than a value quietly
made plausible.

## Where the regressions could still be lying

Four mutations were verified red: filtering to subjects, truncating the newest
instead of the oldest, widening the window to an hour, and dropping
`window_start`. Each was run on a scratch copy of the merged tree rather than
of the tree the fix was written against, because D-S12 is the precedent for
mutation checks that were true when written and never re-run.

What none of them covers: **the twenty-minute window has never been exercised
against real volume.** Every fixture in `test_sprint12.py` uses a handful of
synthetic events. The cap test builds 5,010, but they are identical in shape.
A stream of real messages, with real ties on `ts_source` and real unresolvable
areas, has not passed through this code. The first production cycle is
therefore the first real test, which is the same sentence this repository
wrote about the live path one release ago and should stop having to write.

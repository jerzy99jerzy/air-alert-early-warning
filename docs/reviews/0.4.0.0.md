# Pre-push review, 0.4.0.0

Sprint 5. The scheduled work was the classifier redesign; it was not run, and the
reason is recorded as a decision rather than a slip (D-011). What ran instead is
the part of the source layer that decides whether the corpus, once collected, is
worth anything: a state for the case the model could not express, and a count for
the messages that pass unseen.

## Findings

**F26 closed. The fourth state.** `AlertState.PARTIAL_CLEAR`. Kept distinct from
UNKNOWN deliberately: UNKNOWN means the source said nothing, PARTIAL_CLEAR means
it said two things that disagree. Folding them would discard the fact that the
source spoke, and a contradiction is evidence while silence is not.
Disposition: fixed, with the guard test that an ordinary all-clear is still CLEAR
so the new state cannot quietly swallow the case it was carved out of.

**F27 closed. The window.** Post ids compared across polls. The load-bearing
half is not the count, it is that an unmeasurable gap prints `unknown` rather
than `0`. A first poll has no baseline and a page without ids has no observable;
in both cases zero would be a claim the code cannot support.
Disposition: fixed. MT12 and harness A11.

**F14 closed after two slips, and it paid for itself immediately.** The harness
had passed on every run since it was written, which is also what a harness that
asserts nothing does. Ten controls disabled one at a time; the guarding attack
must go red. **The first run killed 7 of 10.**

The three survivors were the finding of this sprint:

- **F38.** A4 could not fail. Its table failed the association condition as well
  as the alarm rate, and its assertion matched a substring the *passing* reason
  also contains. Present since sprint 3.
- **F39.** A9 never reached the parser. Single-quoted class attributes against a
  regex written for double quotes; nothing matched, so `messages=0` and the
  never-raise contract was asserted about code that never ran. Present since
  0.3.0.0, where the review recorded A9 as closing MT7 for the live adapter.
  That claim was false for two releases.
- **F40.** A11, written this sprint, tested the unknown-versus-zero decision on
  the one path that returns before reaching it. Caught the same afternoon.

Disposition: all three fixed, 10 of 10 killed after. A7 carries no mutation and
is printed as unverified on every run rather than counted as covered.

**F41. CI restated the gate.** Three jobs duplicating checks `verify` already
runs, in the repository whose README says CI does not do that.
Disposition: fixed, jobs removed, with the reason left in the file so the next
person to add a check does not re-add a job beside it.

## Cost, measured rather than discovered later

`harness-mutation` copies the tree and runs pytest once per mutation: roughly 7
seconds, taking `make verify` from about 4 to about 11. It is in `verify` rather
than beside it, because a check outside the gate is a check that does not run,
and this particular check has already been deferred twice.

## What was deliberately not done

The pattern table still scores 0 of 20 and its pins still hold. The gazetteer
(T15) needs a reference dataset that does not exist in this repository. The
means-as-message-class rework (T16) needs the corpus to answer how a means
message joins an alert by area and time window, which is a question about the
channel's behaviour and not about our model.

## The honest reading of this sprint

Two defect classes closed and four found, all four inside the machinery that
exists to catch defects. That is a good sprint by the repository's own standard
and a bad sign by any other: the harness was the most persuasive artefact here
and it was measuring less than it claimed for two releases.

It is also the third consecutive sprint whose work is inside the tree. T19 has a
window and does not shrink by writing code, and the same is true of T11, whose
two conversations still have no date and gate the shadow-mode start on 24 August.
Sprint 6 is not an editor sprint or it is avoidance.

## Documentation audit, same release

Every document re-read against the tree rather than against the last review. Two
defects, both stale-description rather than wrong-behaviour: F42, a threat row
citing a test that has never existed, and F43, an architecture diagram missing
the only wired live source. Neither left a control unguarded; both left the
documentation claiming something about how a control is guarded that was untrue.

The pattern is now three documents in three releases (F32, F33, F42, F43). The
structural reading: every check in the gate that touches documentation checks
*shape* rather than *reference*. Counts, numbering, parseability, version pins.
The citation check added here is the first that resolves a claim to the thing it
names, and it found a three-release-old defect on its first run. The remaining
unresolved surface is prose: nothing verifies that a sentence describing the
tree is true of it, and no cheap check will.

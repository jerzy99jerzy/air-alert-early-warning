# Review, 0.23.0.0

Carried out on 2026-08-11, before the push, against the release that built
S9's observability layer. D-021 asks for this on a major release.

**This is the first release in several where the acceptance criteria were
written by someone other than the person implementing them, and months
earlier.** `docs/OBSERVABILITY.md` section 9 has held seven criteria since
2026-08-09 under a header saying NOT BUILT. That changes what a review is for:
the question is not "is this good" but "does it meet what was written down
before anyone knew how hard it would be".

## The seven, one by one

| Criterion | State | Where |
| --- | --- | --- |
| Console verbosity does not change the sink | **met, structurally** | `RunLog` takes no verbosity argument at all, so identical input gives byte-identical JSONL by construction. The test asserts the *signature*, because the thing to catch is a later refactor adding a level |
| Null with a reason, renderer prints unknown | **met** | `Unknown` carries a mandatory reason; a bare `None` is dropped rather than written |
| Refused poll produces a degradation notification within one cycle | **not met** | needs a notifier; S10 |
| No message text under default settings | **met** | canary fixture, six body-shaped field names, redaction visible in the line |
| Killed mid-write leaves a whole line or none, reader reports the gap | **met** | asserted against a killed child process |
| `tools/progress.py` replaying agrees with the live view | **not met** | there is no live view |
| Domain lint fails when `mavo/` imports the reader | **met** | plus a second assertion in the suite |

Five of seven. The sprint is declared partial and the document says so beside
the criteria rather than in a changelog nobody rereads.

## What was decided rather than implemented, and why it is worth naming

**A bare `null` is dropped from the line.** The criterion asked that unknowns
carry a reason. It did not say what happens to a `None` a caller passes with no
reason attached. Writing it would create exactly the artifact the criterion
exists to prevent - a null a consumer has to guess about - so it is dropped and
a test pins that. This is an interpretation of the spec, not a reading of it,
and it is recorded here so it can be disputed.

**`from_environment` returns `None` rather than a no-op writer.** A silent null
object is convenient and lets a run believe it is recording when it is not.
The caller is made to decide.

**The bodies switch logs itself on every open, not once per process.** A reader
holding one rotated file must be able to see the weakening from that file
alone.

## What this release does not claim

- **The sink is not exercised by a real run.** There is no channel-polling
  loop, so every line in every test came from a test. The design has never met
  a 72-hour run, which is the only thing that will find its real defects.
- **Rotation is tested at 800 bytes, not at 8 MB.** The mechanism is the same
  and the sizes are not, and nothing here has watched a real file rotate.
- **`ms` timings are wall clock from an injectable now.** They are not a
  performance measurement and no claim rests on them.
- **The interval distribution is recorded, not yet checked.** T27's acceptance
  asks that the recorded distribution over 72 hours match the configured range.
  This release makes the recording exist. The check is the run.

## The thing a reader of the last three releases should notice

Every release since 0.21.5.0 has found defects in the release before it, and
three of the last four found defects in claims rather than in code. This one
found none, which is either because the acceptance was written in advance by
someone not yet invested in a particular implementation, or because it has not
been read carefully enough yet. **The honest position is that a review by the
author of the code under review has now failed to catch its own errors four
times this session**, and the two that caught them were an operator asking a
direct question and an operator's interpreter printing a warning.

No mechanism is proposed for that. It is recorded because the count is the
useful part, and because a review claiming to have checked itself is the
specific thing this document should not do.

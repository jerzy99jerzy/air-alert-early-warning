# Review of 0.37.0.0

Version: 1.0 / 2026-08-21
Baseline: `main` at 0.36.0.1, deployed and verified. This is the documentation
sprint: no runtime path changes, one CI line, and every operational document
brought level with what the last week actually measured.

---

## The debt this release pays, stated as its principle

The week of 2026-08-14 to 2026-08-21 produced more field findings than any
since the project started: three register entries, a withdrawn pin, a closed
hypothesis, a reopened one, two deploys, one withdrawal, and a probe that
reversed a ten-day-old conclusion. Almost none of it was in the tree. It lived
in session transcripts, in a handover, and in the changelog's dated entries -
places a reader does not start from.

The principle, which is D-015's documentation corollary: **a document that
describes the system is wrong from the moment the system moves, and the only
honest states are dated-and-current or dated-and-superseded.** This release
moves every operational claim into one of those two states.

---

## DEPLOYMENT.md: structure, not arithmetic

The installed-package table said 0.32.2.0. A section four screens below said
0.32.7.0, deployed and proven. Both sat under one `Host state measured` line,
and the handover said 0.32.9.0, and the truth was none of the three - the
host reads 0.36.0.1 by symbol and digest.

The repair is structural. The table had no rule about *which moment* it
describes, so it accreted moments. Now: the table is the newest reading and
nothing else; a deploy-history table below it is every reading, including
0.36.0.0's row whose fate column says **withdrawn after 14 hours** with F110
beside it. A document that keeps history in dated rows cannot contradict
itself by keeping it in prose.

Three new sections, each paid for this week: the host's actual network (the
IPv4 black hole that doubles every fallback's cost; the public site the host
cannot reach and this session probed anyway); `/var/tmp` staging, with the
unexplained `/tmp` deletion recorded as unexplained; and **counting refusals
without repeating F110** - attempts, finishes and refusals as three counts
that must reconcile, because a rate computed from one token measures that
token's printer.

## T39: an entry that reverses itself, in public

The 600-packet probe T39 asked for on 2026-08-11 finally ran, and it ran both
halves in one window so a difference between probes could not be a difference
between hours. ICMP: 600 of 600, at 99.8% power against a 1% rate. TCP, same
window, same address: 10.7% failed. The collector, same window, own cadence:
zero of 34.

Packet loss is closed at the power the entry demanded. And the closure the
entry recorded on 2026-08-11 - rate limiting, dismissed after ten requests in
fifty seconds all returned 200 - is **reopened**: an n=10 probe has no power
against a limiter metering a longer window, and the new data selects on
exactly what a limiter selects on, protocol and rate. The entry now also
records that step 4 shipped before steps 2 and 3, against its own ordering,
and that the warning it carried came true in a stronger form than written.

An entry that can say "this closure was wrong" out loud is the register
working. The alternative is the closure staying quietly load-bearing.

`python-version: ["3.11", "3.14"]` sat under a comment claiming the version
developed on was covered. It was not. Every "gate green" in every release note
since the workflow existed was a 3.12 reading CI never took. The matrix now

## What this release deliberately does not touch

**Section 8a stays empty.** The latency distribution exists, the T40 caveat
about its two-cadence mixture is now written, and the row still waits on T66,
because a number whose tail cannot be attributed is a number that reads as
more measured than it is. The pressure to write it grew this week; the reason
not to grew more.

**No transport changes.** T69's window runs to 2026-08-22 08:52 UTC and the
retry has still never been observed firing. Touching the code it lives in
before that reading would reset the one clock that is finally clean.

**The rate-limit question stays open.** The next step is the same probe at
production cadence - hours, not minutes - and it is written in T39 rather
than half-done here.

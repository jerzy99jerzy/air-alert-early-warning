# Review 0.43.0.0: what deploy day found, repaired, and left open

Version: 1.0 / 2026-08-29

Third release of one day, and the only one whose contents were dictated by the
other two: everything here was found either in the 0.42.0.0 review or in the
first hour of that release running on `vm-mavo`. `[measured]` means executed
in this repository's container or read from the host during the deploy; no
figure below is projected.

## 1. The prior review's points, closed against numbers

The 0.42.0.0 review flagged four things and promised them to this release.
Their state, in its order:

**Point 1, `attempts()` materialises the window.** Repaired by streaming, and
the claim is scoped honestly: the reader holds one row, the latency vector is
kept whole because the median needs it. One synthetic year, 955,570 rows,
`[measured]`:

| | 0.42.0.0 | 0.43.0.0 |
| --- | --- | --- |
| full-window measure | 3.6 s, ~248 MiB of dicts | 2.1 s, no dict tuple at all |
| guard | none | `isgenerator` assertion, red when the stream is rebuilt as a list |

**Point 2, `newest_page_id` scans on every poll.** A covering index on
(`feed`, `last_id`) takes the pre-fetch cursor read from 112 ms to **0.7 ms**
over the same year `[measured]`. The regression asserts the *query plan* names
the index, not a timing, because a timing test is a flake and a plan is a fact
about the query; verified red with the index deleted from the schema.

**Point 3, no lock on concurrent collect.** Decided rather than patched:
D-039 records the arithmetic (10 s fetch deadline against a 30 s timer,
`systemd` serialising the unit) and why the one reachable overlap - a manual
invocation beside the timer, which deploy day itself produced - is benign
(`MAX` cursor, content-hash idempotence, attempt rows that cannot collide).
Reopen conditions named: a deadline configured at or above the interval, or a
second writer.

**Point 4, the instrument exists in no operator document.** It also, it turned
out, existed on no operator *machine*: `pip` installs the package, not
`tools/`, so `tools/attempts.py` could not run on the only host that has a
production `feed_attempts`. D-038 moves store-reading instruments into the
wheel as `mavo` subcommands, which puts them under `manual_audit`'s
documentation checks; 4.9 documents it; the tools path survives as a
forwarding shim.

## 2. What the wider revision found beyond the review

**F127, the sharpest of the day.** `docs/MANUAL.md` 4.5 told an operator, on
deploy day 2026-08-29, that this command reports `parsed=0` against live
content and that `--stub` is the only path that parses anything - against
eighteen days of the host measuring `parsed=19` of 20 every 33 seconds. Two
paragraphs later a sentence promised to stay "until the cursor exists" and
outlived the cursor by a release. Same class both times: **a claim that names
its own expiry has nobody watching the date.** The gate stayed green because
`manual_audit` checks that transcripts reproduce and options are documented -
shape, not truth - and the one transcript in 4.5 exercises the one path the
false paragraph endorsed. No prose-truth checker is added, deliberately; what
is added is the smaller missing thing, a documented `mavo attempts` the audit
at least knows exists.

**The flow diagram was two releases behind on its own subject.**
`DATA-FLOW.md`'s single diagram showed one stream into the store while the
kind stream (T16) had run beside the alerts since sprint 7, and knew nothing
of the attempt row or the cursor back-edge. Version 1.1 draws all three, and
the back-edge is dashed and named as the diagram's one exception to
left-to-right flow: `collect` reads exactly one scalar from its own record.
The loss table gains the attempt log's row, whose "if it were invisible"
column is T66's founding sentence.

**The host document described a machine three readings old.** DEPLOYMENT 1.14
now carries today's host: installed 0.42.0.0, behind by one, the migration
paragraph converted from prediction to reading (three `[STORE-MIGRATED]`
lines, once, no row lost, `skipped` unknown-then-zero, pre-install copy
`2490e966…d2892` as the point of return). One reading is still owed and the
file says so: the `.dist-info` mtime, with its command inline. A note for
honesty: the 0.42.0.0 review said the `Installed` row is watched by nothing;
that was half wrong - `check_the_host_release_distance_is_counted` reads it
and forces the `Behind by` arithmetic to match, so the *pair* cannot drift
apart. What nothing can watch is the pair against the machine, and that
remains true and unenforceable from a repository.

**Nine and a half hours of silence with no base rate - T82.** The gap was
verified from three vantage points during the deploy (curl from two networks
and the collector's own transport, all reading top post `334744`), the
pipeline reported it correctly, and nobody can currently say whether it is
the tail of the channel's distribution or an event. The task lands the gap
distribution from both the host store and the corpus, separately, because one
is raid nights by construction and the other is whatever the timer saw.
D-034's field, when it ships, will be read against exactly this question.

**Assets: the most common abnormal state has no picture.** The web-tier
illustrations cover `ok`, `quiet` and `blind`; `degraded` - 20.5% of cycles
by D-034's own measurement, and nine unbroken hours of it today - is not
drawn. Consumer-side work, noted for `mavo-site` rather than taken here. In
the same sweep, the consumer's map preview (`podglad-mapa.html`,
2026-08-10) confirms T47's open second item from the artifact itself: the
legend offers missile, drone and *type unknown*, so a `glide_bomb` or
`artillery` declaration renders as "typ nieznany" with nothing telling the
reader the collapse is deliberate.

## 3. Found while repairing, and not dressed up

**Opening the store costs the file, and the streaming claim must not hide
it.** The child-process benchmark for point 1 peaked at ~279 MiB - and so did
a control that only *opened* the store and read nothing `[measured]`:
baseline open, bare iteration, and full measure all peak within 1 MiB of each
other on the 128 MiB synthetic file. The reader is O(one row); something in
the open path is O(file), unattributed as of this review. It predates this
release (the open sequence gained only an idempotent `CREATE INDEX IF NOT
EXISTS`), it is invisible at the host's current 18 MiB, and it grows with a
table that has no retention. Left open by name rather than folded into the
win: the 3.6 s -> 2.1 s and 112 ms -> 0.7 ms improvements are real, the
memory story is "no longer *additionally* O(window)", not "small".

**The README precision ceiling is measuring noise.** It has moved 23 -> 22 ->
23 in three releases tracking how many decimals the coverage pin happens to
carry, with no new claim of false precision anywhere in the file. Candidate
repair: exclude pin-quoted figures from the count. Not taken today; the
comment above the ceiling records the churn so the next mover sees the
pattern instead of the number.

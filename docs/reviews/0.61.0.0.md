# Review 0.61.0.0: weeks set against weeks

Version: 1.0 / 2026-10-18

Mandated by D-021 on the minor bump: a new command, a new file and a new unit
pair. Against `main` at 0.60.0.0 (`bd88ae8`). **Written by the session that
built the release.** One round by an agent run given the tree and a brief, but
not the session's reasoning, which set mutants and built windows instead of
reading the code. It was cut short before it wrote a report; its scripts and
their logs were read by the session, and every finding below was re-run here
before it was acted on. `[measured]` means executed in the session's
container; `[reported]` means taken from the agent's logs.

## 1. What was asked

On 2026-10-18 the operator asked for a page that sets the last weeks of the
alarm record beside the weeks before them, the reader choosing how many of
each as far back as ninety days, and shows what was happening in Ukraine
whenever RCB raised an air alert in Poland; he approved its mockup the same
day and asked for the release to be prepared for the repository and for
production.

## 2. What was built

`mavo/analysis.py`, which reads the window once (`read_inputs`) and computes
the whole file from that reading (`analyse`), so its arithmetic can be held to
windows written by hand. `mavo analysis --store --out [--as-of]` writes it with
`report.write_analysis`, the writer every file uses, and prints what it cost.
`tools/contract_check.py` gains `check_analysis`. D-064 records the rules;
`docs/DEPLOYMENT.md` quotes the unit pair and the order of the install.

## 3. The round: sixty mutants and five scenarios

The agent set sixty hand mutants on the module, each one change, and ran
`tests/test_analysis.py` and the contract check against each: **58 survived
both** `[reported, re-run: measured]`. It then ran each against the
production export of 2026-10-18 and compared the file with the one the
unmutated module writes: **33 of the 58 changed it** `[reported]`. The tests,
written beside the module by its author, asserted each block's presence and
plausibility, and the shape survives almost any arithmetic (F201).

Its five scenario scripts built windows aimed at the places a count could
take silence for calm. Re-run here against the tree they were written for,
they found seven defects (F200), each latent on 2026-10-18 and each repaired
with a case in `tests/test_analysis.py`:

- **Major, repaired.** A rule's firing in a stretch the RSO list was not read
  counted as a firing and as idle, while the observed days, its denominator,
  left the stretch out: eight idle firings over an outage in the scenario,
  none after the repair `[measured]`.
- **Major, repaired.** Episodes inside the same outage counted as on the RCB
  record and without an alert, so the page would have read "none of 8"
  `[measured]`. An episode is now on the record only if the list was read for
  every minute of it, or if an alert fell inside it.
- **Minor, repaired.** A firing with an alert inside it was idle when the band
  was not observed at the alert's minute; idleness now looks at every alert.
- **Minor, repaired.** A choice's weakest day was taken from the calendar span
  between its first and last week, an unusable week between them included: a
  day with nothing seen named the weakest day of weeks that do not hold it.
- **Minor, repaired.** From Monday to Wednesday, while the week running is not
  usable, the run of long days was always zero: the walk began in that week.
- **Nit, repaired.** A file written in the first minute of a Monday held
  twelve weeks under a window that said thirteen.
- **Nit, repaired.** An alert of the minute after the window's last whole one
  was in the list and in no week.

**Considered and left as they are**, each the rule's own consequence and named
in D-064: an alarm that begins in the very minute of the switch starts no
episode, since its minute before was measured by the other instrument; runs
of one read cadence on either side of a hole are reported as one cadence,
while the hole itself is in `rcb.unread` and out of every count; and a source
silent for three hours at the end of the window counts those hours out.

**The consumer had the same shape** in two sentences chosen by a raw count, a
reading of "no alerts" where the list was not read and of "the record begins
later" where the baseline was read and quiet: its F-S137, repaired in its
4.92.0.0 with a mutant in its register.

## 4. The repairs, held to the mutants

The sixty were adapted to the repaired module where a repair moved their
line, and six were added for the repairs themselves. Against the new
`tests/test_analysis.py`, whose every expected figure is worked out in the
test from a window written by hand, **63 of 66 are killed** `[measured
2026-10-18]`, each by the test named in section 7. The three that survive:

- **The bootstrap's filter on negative slopes**, removed. A resample with a
  negative slope needs leads that fall as the rings move east, which no
  window short of a noisy record produces; a case for it would be a fixture
  written to reach a line.
- **The coarse minutes held to the minutes read**, removed. Equivalent while
  the unread stretches and the reads come from one rule, as they do: a pair of
  reads further apart than the outage threshold is never a coarse pair.
- **A group's alerts taken by the date in their stamp**, against
  `_day_of`. Equivalent, because the stamp is already on the Warsaw clock.

The contract check kills none of the 66, by design: it holds the shape a
reader relies on, and the arithmetic is the test module's.

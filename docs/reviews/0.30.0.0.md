# Pre-push review, 0.30.0.0: one instrument, and what it is allowed to claim

Version: 1.0 / 2026-08-13

The release adds `tools/latency.py` and nothing else executable. This review is
short because the surface is small, and it exists because the interesting risk
in a measuring instrument is never that it crashes.

## The four ways this tool could have lied

**By interpolating.** A p90 computed between two observations is a number
nobody measured, printed with the authority of one that was. Nearest rank, and
a regression asserts it on a four-element list where the two conventions
disagree.

**By tidying.** A negative lag is a post received before its own timestamp:
two clocks that do not agree. Clamping it to zero would improve every summary
figure and destroy the only evidence that the measurement has a systematic
problem. Reported separately, with the most negative value.

**By naming.** The tool measures publish-to-receipt. Calling that "the
channel's latency" would assert a decomposition it cannot perform, because our
own poll interval is inside the number. The interval is printed beside the
figures, the upstream is an upper bound, and the string "channel latency" does
not appear in the output. There is a regression for the string.

**By scale.** T40 asks for a week. The instrument refuses less, and the
`--allow-short` path prints `NOT A T40 MEASUREMENT` on the summary. This is the
lesson of the twenty-message hand sample, which is a correct measurement of
something nobody wanted to know and reads like a correctness rate.

## What this release does not contain

The measurement. It needs seven days of a collector that has been running for
two, on a host this session cannot reach. The table in `docs/CHANNEL.md`
section 8a is present and empty, which is the honest state: the instrument
exists, the number does not, and the poll-interval argument in D-027 stays
unresolved until it does.

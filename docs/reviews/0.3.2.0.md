# Pre-push review, 0.3.2.0

An external consistency audit of the whole tree: the gate re-run, every claim in
every document re-read against what the code measures, every cross-document
reference resolved. Six defects, F31 to F36, all in documentation or duplicated
state, none in decision logic. The defect log in `docs/METHODOLOGY.md` carries
the full entries; dispositions here.

## Findings

**F31. Stale coverage pin in `STATUS.json`.** Fixed: the block now carries the
number the gate produced (96.34 on Python 3.12, after this release's tests).
The class fix is a decision, deliberately not taken unilaterally: either
`docs_audit` regenerates the measured block from a gate run, or the block is
dropped and the review file becomes its single home. Owner: 0.4.0.0.

**F32. README described the release before last.** Fixed. The structural gap
remains open as a decision: the "Measured claims" section is exactly the surface
`lint_limitations` exists for and is not registered in it. Registering numeric
claims would mean the lint re-runs part of the gate; the cheap alternative is
moving all numbers out of the README into `STATUS.json` and linking. Owner:
0.4.0.0, together with F31, because they are the same defect class.

**F33. MT9 cited a decision that did not exist.** Fixed: D-010 written, T13
closed. One epistemic downgrade made while writing it: "the channel is the
shared upstream of both APIs" was recorded as fact and is an inference. The
correlation (load-bearing for MT9) holds under any internal topology; the
relative latency of channel versus APIs does not, and sprint 5 measures it
before any claim about being "one step earlier" is repeated outside the tree.

**F34. MVP contradicted its own schedule.** Fixed, recorded as a scope change in
the document itself per the standing rule.

**F35. Means layer unpinned.** Fixed, pinned at 4 of 20 with the same
flip-deliberately wording as the other pins.

**F36. Hardcoded version in User-Agent.** Fixed, derived from `__version__`.

**Open: the coverage floor is nearly binding, and that is a measurement-scope
question.** `transport.py` sits at 68% because `UrllibTransport.fetch` is the
one genuinely network-bound function and the environment cannot exercise it.
Options: (a) exclude that function from the measurement with an explicit pragma
and a recorded reason, which makes the floor track the testable surface but is
also how flattering exclusions start; (b) leave it counted and accept that any
future network-adjacent code presses the total toward the floor; (c) lower the
floor, which the ratchet rule (T9) exists to prevent. Not resolved here because
it changes what the coverage number means, and that is the maintainer's call.
Owner: 0.4.0.0.

**F14, third owner.** The harness has never been observed failing; slipped at
0.3.0.0 and 0.3.1.0, now owned by 0.4.0.0. Per the 0.3.1.0 review, a third slip
means the README claim is weakened instead. One argument for landing it now
rather than weakening: sprint 5 rewrites the classifier the harness guards, and
a harness that has never failed is thin evidence to rebuild on.

## What was deliberately not done

The classifier was not touched. The pins at 0 of 20 stand, per F28: a table
patched against twenty messages from twenty minutes of one evening repeats the
defect it would claim to fix. `--save-raw` was added precisely so the redesign
has a corpus instead of a sample.

content: 0 of 20, unchanged, pinned. Manifest regenerated and verified with

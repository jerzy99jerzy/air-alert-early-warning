# Pre-push review, 0.29.0.0: a documentation audit

Version: 1.0 / 2026-08-13

Scope: every document in the tree, read against the state of the system on
2026-08-13, with the specific question *is this still true* rather than *is
this still good*. Forty-seven documents, 17,086 lines at the moment it was pinned. The release that follows
changes four of them and this file records why the other forty-three were left
alone, because a review that reports only its edits is indistinguishable from
one that only read what it edited.

## Method

Three passes, in order of how cheaply they catch a lie.

1. **Mechanical.** `make verify` already runs `docs_audit.py`,
   `manual_audit.py`, `brief_check.py`, `contract_check.py`, `todo_index.py`
   and four linters. Every pin, badge, README table row, anchor, cited test
   name and document version is compared against the tree on every release.
   That pass was green before this review began and is green after it, so
   nothing in this file is about a number disagreeing with a number.
2. **Version and date lines.** Every document that carries one was listed with
   it. Six do; the rest do not, which is itself a finding (below).
3. **By hand, against today's facts.** The system changed under the documents
   this week in four ways: the consumer went public, the consumer shipped five
   releases, the poll interval changed, and the fetch timeout turned out not to
   mean what its constant said. Each document was read for claims about those
   four.

## Findings, changed in this release

**R-1. `docs/WEBAPP.md` was seven releases behind the thing it describes.** It
recorded `mavo-site` 4.1.0.0; the site has shipped through 4.12.0.0 and has
been publicly reachable since 2026-08-12. Its "what gates publication" section
listed three blockers as open when two had been met and the third, T6, was
consciously overridden by D-025. A document that keeps reading plausibly while
its subject moves is F72's class, and this file has now demonstrated it twice:
the same drift was found and recorded at version 2.5.

Changed: status line, consumer version, the publication section rewritten as
what happened rather than what was planned.

**R-2. `docs/DEPLOYMENT.md` described a sixty-second interval.** D-027 took it
to thirty plus jitter, and running it taught three things the design note could
not have known: the timer measures from activation and coalesces on a default
`AccuracySec` larger than the interval it paces; a failed fetch costs its own
wall clock rather than one interval; and D-027's deciding arithmetic was
therefore optimistic. All three were in the decision log and none in the
operations document, which is where somebody debugging a host at night would
look.

Changed: a "what actually runs" block at the head of section 3, with the
measured gaps and their provenance. The design reasoning below it is untouched
and is why the interval is jittered at all.

**R-3. The README addressed one reader.** It is a precise document and its
precision is the point, but the first thing a stranger meets is a badge block
and a status paragraph containing the phrase "base-rate gated". The project is
public, it is being shown to journalists and to people at the border, and there
was no path through it for a reader who wants to know what the thing does.

Changed: five sections before the thesis, in plain words, with the technical
document beginning immediately after and unaltered. The plain sections state
the unmeasured western correctness rate, the pre-alpha status and the "silence
is not calm" rule as plainly as the technical ones do. Making a document
readable is not the same as making it reassuring, and the test applied to every
new paragraph was whether a reader who stops there has an accurate picture.

**R-4. Line counts and one table row.** Mechanical, caught by the gate, listed
for completeness.

## Findings, deliberately not changed

**R-5. Forty-one of forty-seven documents carry no version line.** Six do:
`CHANNEL.md`, `COMPUTATION.md`, `DEPLOYMENT.md`, `FEED-SPEC.md`, `MOBILE.md`,
`OBSERVABILITY.md`, `WEBAPP.md`. Every document is pinned in `STATUS.json` and
the gate enforces the pin, so the absence is cosmetic rather than dangerous.
Adding a line to forty files in the same release that rewrites four of them
would bury the review in noise. Raised as a task, not done here.

**R-6. `docs/MVP.md` closes S7 while T31, T33 and T34 still carry it.** Named
in `TOLERATED_OPEN_IN_A_CLOSED_SPRINT` at 0.28.2.0 with a check that removes
the entry when it stops being true. **This is the author's decision, not the
reviewer's**: either the S7 row is amended or the three tasks are reassigned,
and either way it earns a `DECISIONS.md` entry. Untouched deliberately.

**R-7. `STATUS.json` records nine shipped sprints where fourteen sprint test
files exist.** Reconciled at 0.28.2.0 by renaming the field to
`sprint_test_files`, which is what it always measured. The README's longer
explanation of the two counts is still correct and stays.

**R-8. The consumer's drift is unchecked and will recur.** Nothing fails when
`docs/WEBAPP.md` falls behind `mavo-site`. The two repositories do not read
each other and under D-020 they must not, so the obvious check is unavailable.
A weaker one is: this file records the consumer version it was written against,
and the producer's gate fails when that string is older than the version in the
last `state.json` it served, which the producer does see. Not built. Named in
`docs/WEBAPP.md` so the next person to notice the drift finds a proposal rather
than a complaint. **A rule without a gate check is a preference**, and this is
recorded as a preference until somebody builds the check.

## What this review did not do

It did not read 172,530 lines of `CHANGELOG.md` or 162,417 of
`docs/METHODOLOGY.md` end to end. Both are append-only records of what was true
at a moment, and a past entry is not stale by being past. They were searched
for claims about the four changed facts, and nothing in either asserts a
present state that today contradicts.

It did not re-derive a single measured number. Every figure in the documents is
pinned and compared by the gate; a review that recomputed them by hand would be
a less reliable instrument than the one already running on every release.

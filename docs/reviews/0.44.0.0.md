# Review 0.44.0.0: the switchover release, reviewed against itself

Version: 1.0 / 2026-08-30

The release that answers the channel's death: the API adapter written the day
the silence was diagnosed, the persistence that makes it deployable, and the
decision (D-040) that makes it primary. Reviewed in the same session that
repaired it, which is the pattern to distrust - so every claim below is
either `[measured]` in this repository's container (Python 3.12.3, inside the
3.11/3.12/3.14 CI matrix) or carried from host readings taken during the
0.43.0.0 deploy and labelled as such.

## 1. Findings on the adapter as it entered this release

**W1, the bloker, repaired here.** `UkrainealarmSource._previous` lived in
process memory while production runs collectors as `oneshot` units: every
poll a first poll, `cleared` zero forever, every episode open forever. The
defining property of the failure is that the map looks normal - alerts raise,
nothing ever ends, and no exit code disagrees. Repaired by a persisted
snapshot with a 360 s freshness ceiling; the ceiling's asymmetry is the
argument (too low delays a clear by one cycle, too high clears a window
nothing observed), and six tests hold the states: fresh licenses clears
across a restart, while stale, missing, corrupt, and future-stamped license
nothing and never stop collection `[measured]`.

**W2, a dead constant, removed here.** `_UNIT_WORD` inverted `areas.py`'s
`_UNIT_CODE` and was referenced by nothing in the package `[measured: zero
uses outside its own definition]`. How it got in: written for a resolver
variant that was then implemented inside `resolve_prose` instead, and the
constant survived because module-level names with docstrings sit outside
`ruff`'s dead-code reach. A gate that cannot see a class of defect is a
finding about the gate; noted, not repaired here.

**W3, open, candidate for the register.** `_resolve` returns None for both
"the map lacks this region" and "the map holds more than one match", and the
caller's stdout says `unresolved` for both. The docstring claims only the
first. An ambiguity is a different finding from an absence - one says the
vocabularies drifted, the other says the narrowing failed - and folding them
loses which map defect to fix. Not reachable on today's payload shapes as far
as measured (all eleven live unresolved names are absences), which is why it
is named rather than repaired in a release that must ship.

**W4, the manual arguing for the defect, repaired here.** MANUAL 4.7 stated
a restart forgets the previous snapshot *deliberately* - true of the
in-process design, and exactly the sentence that would have licensed
deploying it. The paragraph now carries the ceiling argument, and the option
table carries `--snapshot`. A document with a wrong "deliberately" in it is
worse than a silent one, because it converts a defect into a policy.

## 2. The repair, reviewed

The ordering is the part that took thought. The snapshot persists **after**
the store accepts the events: a failed append keeps the old snapshot
standing, so the next run derives the same clears again rather than losing
them, at the cost of a possible duplicate `CLEAR` with a nudged timestamp on
the retry path. Checked against `report.py`'s episode builder `[measured by
reading, not by test]`: a second clear on an empty running set discards
nothing, opens nothing, and only moves `last_close` by one cycle - noise,
where the opposite ordering's cost is an episode frozen open, which is the
bloker back. The atomic write through `.partial` is the 0.43.0.0 deploy's
`scp` lesson applied one layer down: a half-written file under the target's
name reads as corrupt and withholds clears for a cycle nothing required.

Loudness is part of the repair, not decoration. `[NO-SNAPSHOT]` prints on
every production-shaped invocation because the failure it names produces no
other symptom; `snapshot=` on the summary line makes a withheld clear
distinguishable from a calm reading; `[SNAPSHOT-UNWRITTEN]` keeps a
persistent write failure - which quietly recreates the bloker - from being
persistent and quiet at once.

## 3. What this release deliberately does not do

No reconciliation of the channel's frozen episodes: areas the channel opened
before 04:55 that the first API snapshot does not list will stay open, the
API cannot close what it never saw, and D-040 names this as the second cost
of the switch. The pre-switch `mavo report` reading in DEPLOYMENT
establishes whether the set is empty; a mechanism invented here, untested
against the production store, would be a second bloker wearing a repair's
clothes. No filtering of `report` by `source_id` either: the contract stays
one picture of one upstream, with the store, not the report, remembering
which pipe each observation came down.

# Review 0.46.0.0: measured before repaired, and what that ordering bought

Version: 1.0 / 2026-08-30

This release was cut from a reading, not from a diagnosis. The diagnosis said
the API names oblasts, the table is raion-shaped, and 21 of 24 oblasts have
nowhere to land; the reading (`tools/region_levels.py` against `/alerts`,
2026-08-30, 52 regions) said 42 of 52 regions are raion-level, 45 of 52
resolve, and no wrong-level row reaches the store. `[measured]` below means
executed in this repository's container or read off that one live payload.

## 1. The diagnosis was built the way F129 was built

The claim that `Харківська область` resolves at the wrong level was true of
the function and false of the system, because the API never sends that form:
it sends the register's full hromada wording, which resolves correctly. The
form had been constructed from a pattern -- the same move as writing `_KIND`
from the local palette -- and the constructed input was then read as evidence
about the source. Third instance of the class in one working day, same
direction each time. The rule it funds: a claim about what a source says comes
from a captured payload or carries `[unverified]`; a constructed input is
labelled constructed everywhere it appears and licenses claims about the
function only.

## 2. Both defects are real, latent, and now visible when they fire

F130 stays worth repairing at latent: 262 wrong-level pairs in the function's
own domain and not one test on either side of the behaviour `[measured]`. The
repair converts a wrong border distance into a printed refusal. F131 was the
opposite case, latent in review (W3) and live in the reading: Pokrovska,
alerting, in the file, indistinguishable from Vovchansk, absent. One word,
two repairs. The split now prints.

## 3. What the reading licenses next, and what it does not

`regionId` is present, compact and unused; `regionEngName` likewise; the
frozen Donetsk premise of D-041 -- that the API names the parent and never
the raions -- is contradicted by eight `UA14` raions resolving in this same
payload. None of that is acted on here: one reading is not stability, and the
store comparison for the frozen set has not been run. The four missing rows
wait on the KATOTTG register itself, because their codes are the register's
to state.

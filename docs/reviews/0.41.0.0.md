# Review 0.41.0.0: one question the tree answered twice, and what fell out of settling it

Version: 1.0 / 2026-08-29

Two defects and one decision. **The decision came first and the worse defect
was found by implementing it**, which is the opposite of this repository's
usual order and is worth naming: F124 was not visible to any check, any test
or any reading of the documents. It became visible the moment somebody wrote
the one change that would trigger it.

Everything labelled `[measured]` below was produced by executing code in this
repository. Figures about the production host are absent, because this release
has not reached it.

## 1. One question, two answers, decided by which sprint asked

`mavo/store.py` has held `feed_attempts` since 0.38.0.0, with a schema comment
calling it "FEED-SPEC property nine, owed by this project to itself". T66
recorded, for the same class of question about the same collector, that attempt
completeness "lives in journald and in `run.jsonl`, **not in the store**". Both
sentences are in the tree, both are load-bearing, and they disagree.

Neither is wrong about what it was looking at, which is why the disagreement
survived. T66's reason is exact: *a poll that never returned writes nothing, a
quiet channel writes nothing, and the two are the same row count*. That is a
true statement about the `events` table. It is a false statement about a table
with one row per attempt. The two entries were describing different objects and
using one noun for them.

**D-036** settles it on a discriminator that is neither the feed nor the
sprint: **does anything in the product read the record back?** The report path
reads the store and only the store, so a fact the contract must publish lives
in the store; a fact only a person greps lives in the sink.

That reverses a rejection in **D-034**, which declined "poll outcomes as rows
in the store" partly because it "grows the store by 2,861 rows a day". The
growth was asserted and never costed. Measured:

| Quantity | Value |
| --- | --- |
| Bytes per attempt row, one refusal in eight | 146 |
| Rows per day at the 33 s cadence | 2,618 |
| Growth per day | 372 KiB |
| Growth per year | 133 MiB |

`[measured, 2026-08-29, on a synthetic store in a container - not the host.
The host figure is a deployment reading and is owed.]` The refusal share used
here is T39's measured 11.6%, and refusal rows are the larger ones because
they carry the exception text.

**Whether reversing D-034 on this is right is the part worth arguing with.**
The case for it: the store already holds attempts, adding a second mechanism
means two records of one event and a drift risk this register has logged eight
times. The case against: `run.jsonl` has rotation and retention and the store
has neither, so the reopen condition in D-036 names retention as the answer
when the table outgrows a reader, and until somebody writes it the growth above
is unbounded.

## 2. The guard whose remedy deletes the evidence

`_refuse_an_older_schema` refused a store missing a column from any of four
tables, with one remedy for all four: rebuild from the raw corpus, per D-013.

D-013 is about a **derived** artefact. `events` and `kind_events` are derived,
and a rebuild restores every row. `feed_attempts` and `communiques` are not
derived from anything, so a rebuild is an unrecoverable deletion. The guard
protects the store and then tells the operator to destroy the half of it that
cannot be reconstructed.

**This release would have fired it.** D-036 adds one column to
`feed_attempts`. Sequence on the host without the repair: deploy, first poll,
`SchemaMismatch`, exit 7, every 33 seconds, with a message instructing a
rebuild that discards every attempt row `vm-mavo` holds.

`[measured]`, the three shapes, built by hand because no older version of this
class exists to run:

| Store shape | Before | After |
| --- | --- | --- |
| `events` one column short | refused, "Rebuild" | refused, "Rebuild", scope named |
| `feed_attempts` missing `elapsed_s` | refused, "Rebuild" | column added, row survives, `elapsed_s` NULL |
| `communiques` missing a column this version cannot type | refused, "Rebuild" | refused, "copy the file aside" |

The third row is the one that keeps this from being a hole. Accepting any
recorded table that lacks any column would put the store back in the state the
refusal exists to prevent.

**The class is the register's fifth "mechanism shaped like a guard", and the
worst of them.** The earlier four failed to protect. This one protected
correctly and then handed the caller the instruction that does the damage,
which is worse: a reader following the message believes they are recovering.

**The migration is not silent**, and that was a second decision rather than a
detail. `EventStore.migrations_applied` names what was added and the commands
print it once. `test_an_ordinary_open_reports_no_migration` holds the other
half, because a line printed on every open is noise and teaches a reader to
skip the one that matters.

## 3. An argument that rested on a check saying something else

T80's case that T71 could not unblock D-034 cited `tests/lint_domain.py` as
asserting "the pipeline never reads its own reader". `[measured, 2026-08-29]`
that function is `check_the_pipeline_does_not_import_its_reader` and it asserts
that no module under `mavo/` imports `tools.progress`. It would pass a
`mavo/report.py` that opened `run.jsonl` directly.

The conclusion is still true, on grounds the entry did not give: two processes,
a `oneshot` and a loop, sharing only the store and the filesystem. **F125**,
class three. It cost nothing and it is logged because the register's value is
that it records how conclusions were reached, not only whether they were right.

## 4. What T47 already had, and nobody looked

`check_every_kind_is_documented` has been in `tools/contract_check.py`, called
from `main`, and green in the gate. T47's first acceptance criterion asks for
exactly that and the task read `ready`. **F118's third instance**, after T62
and T72, and the mechanism is the same each time: nothing in this project ever
prompts anybody to go looking for good news.

The third criterion was genuinely missing and now exists. It is built as the
hardest case rather than the easy one - a night with active alerts in a border
oblast and a westward vector across three oblasts, so every conjunct except the
kind is satisfied - and it is paired with a control asserting the same shape
fires when the kind is MISSILE. Without the control the assertion passes
against a fixture that could never fire for any reason at all, which is the
fixture-arranged-by-the-implementation failure this register has logged six
times.

## 5. What this release is not

**Not sprint work.** `TODO.md`'s "Where the project is" paragraph was rewritten
at 0.37.0.0 precisely to stop repairs and instruments being counted as progress
toward beta, and this release is repairs and an instrument. The open tier-1
items need counsel (T6), conversations (T11), a population that has not
appeared (T36), or a host (T39, T40, T54, T73). None shortens by writing code.

**Not a measurement.** `tools/attempts.py` has never been run against a window
with rows in it. This project shipped `tools/latency.py` at 0.30.0.0 and left
it unread for nine releases, and the entry recording that is three screens
above the one closing T66. An instrument that exists and has not been read is
not evidence.

**Not the contract field.** D-034's `state.json` field composes from rows the
host does not have until this release runs there. Shipping the field and its
first production value together would put an unread number on a public page.

## 6. What the next release owes

1. **Deploy, then read.** The `[STORE-MIGRATED]` line, counted over a window
   rather than observed once: appearing on every poll means the migration is
   not sticking.
2. **Run `tools/attempts.py` against a week**, and paste the row into
   `docs/CHANNEL.md` 8a with T40's two-cadence caveat.
3. **Then** D-034's field, against a table with rows in it.

The order is not preference. Each step is the input to the next, and the
release that takes step three before step one publishes a number nobody has
looked at.

# Review, 0.28.0.0

Carried out on 2026-08-13 against the release that added a measuring
instrument and quadrupled the poll rate.

## The thing this release is most likely to be misread as

A second source. It is not, and the module is built so that it cannot quietly
become one: no `poll`, no `ThreatSource`, no `content_hash` on its reading.
`api.ukrainealarm.com` and the Telegram channel draw from the same upstream,
which the contract negotiation established months ago. **Two views of one
origin agreeing is not corroboration**, and the sentence "two sources confirm"
would be false if it ever appears in this project.

What it does buy is two numbers that do not exist today and cannot be produced
by any amount of work inside the current pipeline:

- **Latency**, end to end, from a state change at the source to a rendered
  report. That is T40, one of the two things between here and beta, and it
  cannot be measured against a channel post alone because a channel post has
  no upstream timestamp to compare against.
- **Coverage**, meaning alerts the API reports that the parser did not.
  Hand-labelling cannot produce this: a labeller reads the same messages the
  parser reads, so a message the channel never posted is invisible to both.

## What went wrong while building it, and what caught each

**The architecture check caught the design mistake in the same run.** The
first version opened its own urllib connection, and
`test_the_network_seam_is_one_file` failed immediately. That check exists
because network behaviour in two files is network behaviour nobody can audit
in one place, and it has now paid for itself against its own author. The
repair added an optional `headers` argument to `Transport.fetch`, which is
also where the key belongs: in a URL it would reach every proxy log between
here and the provider.

**I invented a method that does not exist.** `AreaTable.knows_oblast` was
written into the adapter from memory rather than from the file. Caught by
running it.

**The two vocabularies did not join.** The API appends a word the channel's
hashtags do not, so `oblast_slug` returned an empty string for every region.
Had that shipped, the coverage measurement would have reported the parser
missing everything: **the most flattering possible error for the API and the
most damning for the thing being measured.** Caught by printing the parse
rather than by a test, which is worth noting because a test written by the
same hand would have used the same wrong assumption.

## D-027, and the honest shape of its evidence

Thirty seconds rather than 120. The freshness argument is real but secondary;
the argument that decided it is the cost of a missed poll at a measured
one-in-eight failure rate, where a run of two failures went from 390 seconds of
blindness to 90 against a 600-second threshold.

**The politeness evidence is weaker than it looks and the entry says so.** Ten
requests in fifty seconds all returned 200, which is a burst measurement. A
limiter that tolerates a burst can still act on a sustained quadrupling. What
makes this defensible rather than reckless is that T55 shipped two releases
ago: if the source starts throttling, the refusals now carry their elapsed
time and exception class, and one night of journal will say so. **The
unreachable rate is both the reason for the change and the test of it.**

## What is still not measured

Everything the adapter was built to measure. The module exists; no comparison
run has happened, because that needs the key on the host and a night of
collection. This release is the tooling, and the tooling is not the finding.

That is the third release in a row that could be written without leaving the
editor, against a backlog whose oldest items — T54, T39, T36 — all need a host
and wall-clock time. The pattern is now four releases long and worth naming as
a habit rather than a coincidence.

## 2. The finding that shipped in this release

**T83, one value wider than the entry asked.** `_KIND.get(type, UNKNOWN)`
folded any well-formed type string outside three rows into an ACTIVE of
unstated kind, silently. The entry already said so. What it did not say: the
Home Assistant integration D-029 cites as one of its three vocabulary sources
lists seven values, not five, and one of them is `INFO`, an informational
message. On that fold it would have raised an alert on the map `[inference
from the cited source's constants; whether this key has ever returned it is
unmeasured]`. Shipped: `INFO` left out of the snapshot and counted; every other
unknown string named with its regions, printed, and written to
`feed_attempts.detail`. Three adapter tests, one CLI test, red-verified by
construction (the attribute did not exist). D-029 amended, not reopened. The
measurement that closes the bracket is one run of `tools/api_kind_compare.py`
on the host, which has not happened since the key went live.

## 3. Findings filed and not paid here

- **D-034's prerequisite was discharged by D-040 and nobody re-read D-034.**
  `feed_state` is decided by the newest *event* stamp, so a quiet stretch
  longer than `valid_for_s` reads `degraded` on a healthy pipeline; D-034
  measured it at 20.5% of cycles and blocked the repair on T71 because
  `collect` had no sink. Since D-040 the API path writes `feed_attempts`
  through `store.record_read`, so the age of the last successful poll is one
  `MAX(started_at)` away, and the consumer's F-S45 heuristic could retire. T71
  is still open, D-034 is still waiting, and the F118 shape - a blocker
  discharged, its dependent not re-read - is the one T66 already recorded.
- **`feed_attempts.items` means two things.** Messages read on the channel
  path, transitions on the API path; a poll against an unchanged snapshot
  logs `0`, which the table cannot tell from "page read, empty". Property
  thirteen of FEED-SPEC, unapplied to this project's own table.
- **`save_snapshot` renames without `fsync`.** Failure points the safe way
  (a corrupt snapshot withholds clears), so low.
- **`cli.py` at 86%, and the uncovered lines are the safe-direction branches**
  of `collect-api`: `[SNAPSHOT-UNWRITTEN]` and `[STORE-FAILED]` after
  `record_read`. The branches that claim to fail safe are the ones no test
  exercises.
- **Consumer `producer.version_read` pins 0.37.0.1** against a producer at
  0.52.0.0; schema 3 is unchanged, so this is stale rather than wrong.
- **F-S65 says this repository's 0.51.1.0 carries a wrong date.** The zip's
  file times put its last commit at 2026-09-01 19:39, which is the date the
  changelog carries. `git log -1 --format=%cI v0.51.1.0` settles it; not
  changed here.

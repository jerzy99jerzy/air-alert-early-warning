# Review of 0.34.0.0

Version: 1.0 / 2026-08-20
Baseline: `main` at 0.33.0.2, gate green on Python 3.12. This release adds one
module, one fixture and nineteen regressions. **It changes no measurement, has
no caller, and ships nothing to the host.**

---

## What this release is, stated narrowly

A parser for the RSO XML feed. It converts bytes into records and stops there.
It does not fetch, store, schedule or render, and `mavo/sources/rso.py` has no
`poll`, so it cannot be handed to the collector without somebody writing the
line that does it.

**That narrowness is the design, not a stage of it.** Where a Polish warning
appears in this product is a decision with a cost that runs the wrong way if
it is made by default, and T68 states it. A reader that could be wired in by
accident is a decision made by whoever wires it.

---

## The three refusals, and why each one exists

**An unparseable page is not an empty page.** A page with no communiques is a
real answer on a quiet day. If damaged bytes produced the same value, this
instrument would render its own blindness as a country with no warnings, which
is the single output the whole project exists to avoid. Damaged bytes, an
oversized body and a doctype all refuse instead.

The doctype guard is worth naming separately. `xml.etree` is documented as
unsafe against entity expansion, this project carries no runtime dependencies
and will not add `defusedxml` for one reader, and an entity bomb needs an
internal subset to declare its entities. Refusing the construct removes the
class; a size limit alone only bounds it.

**A naive timestamp is not converted in the parser.** Every time in this feed
arrives as `YYYY-MM-DD HH:MM:SS` with no offset. `to_utc` takes the zone as an
argument, and refuses an hour the zone maps twice. Choosing silently would be
right for all but one hour of one night a year, and an error that rare is one
nobody finds by reading output.

**A row without an identifier is dropped and counted on the page.** `id` looks
monotonic and unique, but `updated_at` moves on a rewrite, so idempotence has
to key on content, which `Communique.digest` does. A row with no identity
cannot be stored idempotently at all, so it is refused rather than given one.
The count rides on the page because a caller reading only the list cannot tell
a short page from a damaged one.

## What the source does that this project is built for

Two shapes of nothing in one document. `<latitude></latitude>` is present and
empty; `valid_from` is absent from a road message. An adapter that tests
presence reads the first as a value. Both now read `None`, and the collapse is
deliberate rather than convenient: a difference invented between them would be
a claim about the publisher's intent that nobody has measured.

`rso_alarm` reads `1` and `0` in the sample. It looks like the severity
discriminator against MSWiA's three levels and its encoding is **undocumented
and unverified here**, so it stays text. An integer would assert an ordering
this project has not established.

---

## What this release does not do, and what it costs

There is no fetch, so every figure about the feed in `docs/` and in the
handover came from `curl` run by hand on 2026-08-20 and is `[reported]` here.
The reduced fixture is a copy of one measured page, kept verbatim in its empty
elements, because reflowing them into absent elements would edit the evidence.

No table exists yet. A communique has a different issuer, scope and lifetime
from an alert, so it does not belong in `events`, and putting it there would
repeat the modelling error F25 records. T67 carries that.

**The population is thin and the sizing should say so.** Podkarpackie carried
seventeen messages on 2026-08-20 and Pomorskie two, dominated by storms and
water levels. The air-threat categories exist in the scheme and were not
observed in the sample `[reported]`. This is not a second alert stream and an
EPIC sized as though it were will be wrong about its own value.

## The task that did not exist

T66 was described in a handover as needing rewriting. It had no entry in
`TODO.md` and no number in this repository: the highest was T65. A task
discussed for a day, carried across a session boundary and reasoned about in
prose was still not work anybody had agreed to, because the only register that
counts here is the file the gate reads.

It exists now, and it is tier 1 under S9, because `docs/CHANNEL.md` section 8a
stays empty until the latency tail is attributed and the tail cannot be
attributed from the store alone.

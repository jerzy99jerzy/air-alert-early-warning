# Review, 0.27.0.0, and a full reading of the package

Carried out on 2026-08-13 against the tree that shipped `напрямок`. This one
is longer than a release review because the operator asked for a full code
review, so it covers the package rather than the diff. Measurements were taken
by running things; where a claim is a reading rather than a measurement it says
so.

**Shape of the thing being reviewed** [measured]: 4,873 lines of package, 337
tests, 6,079 lines of test, 97% branch coverage on Python 3.12.3, 78 defects
logged with their class, 19 registered mutants and 12 harness mutations, all
killed.

---

## Part 1. The release

`КАБ напрямок Краматорськ` went unparsed on every poll from 2026-08-11 until
somebody read the journal: two messages in every twenty-message window,
roughly seven hundred times. The message carries a kind marker, no declaration
word and no alert state, so it failed the declare test and was counted rather
than resolved.

**The counter did its job and nobody read it.** `ParseReport.unparsed` exists
precisely so that a stale pattern table cannot look like a quiet channel, and
it printed the failing message, verbatim, in every poll's output. The
instrument reported correctly for a day into a journal nobody opened. That is
not a code defect and it is the more useful finding: **this project's
observability is ahead of its habit of looking at it.**

The marker chosen is narrower than T46 proposed. That entry offers treating a
munition's name as a declaration in its own right and warns it would classify
summaries and after-action reports; `напрямок` is a word about something in
flight now. The ordering warning in T46 was re-checked by reading rather than
assumed, and a regression puts the new marker inside a lift.

Prevalence remains unmeasured and the entry says so. One day of live evidence
establishes that the shape exists and recurs; it establishes nothing about 118
nights.

## Part 2. What the full reading found

### R-1. The same code shape has opposite right answers, and the package gets both right

`RunLog.__init__` calls `mkdir` and `stat` outside any guard, so a permission
error kills the process at construction. That is byte-for-byte the shape of
D-S20 in the consumer, which took the public page down at boot and was logged
as a defect there.

**Here it is correct, and the difference is worth stating because it is not
obvious from the code.** The run log is the deliverable of shadow mode: it is
the evidence. A producer that carried on with no log would be running an
experiment and recording nothing, which is the failure this project exists to
refuse. The consumer's counter is a nicety, and its module says so; losing a
statistic to keep a page up is right there and wrong here.

**Nothing in either repository says this.** Two modules, one shape, opposite
correct behaviours, and the reasoning lives in one author's head. The cheap
repair is a sentence in each docstring naming which kind of artefact it holds.
Recorded rather than done, because it is a doc change and this release is
already a major.

### R-2. Broad exception handlers: five, all deliberate, all explained

`cli.py:202`, `obs.py:193`, `report.py:775`, `report.py:863`, `report.py:910`.
Each carries `# noqa: BLE001` and a comment saying why the breadth is the
point. The two in the publishing loop are the strongest: narrowing them would
mean a new exception type somewhere below turns the loop silent, and silence
is the one outcome that function exists to prevent. `report.py:910` disables
the callback rather than the loop and says so on stderr.

No bare `except:` anywhere. No `assert` in package code. No `TODO`, `FIXME`
or `HACK` markers in the package.

### R-3. Coverage is 97% and the uncovered lines are the interesting ones

The gaps cluster in `cli.py` (90%) and `kinds.py` (91%). `cli.py` is argument
plumbing and its uncovered lines are error paths for filesystem failures,
which is defensible. `kinds.py` at 91% is worth a look before the next release
that touches classification, because that module decides what a reader is told
a threat is.

Not a finding, a pointer: this project's own rule is that coverage is a
ratchet and not a target, and 97% with a 95% floor is doing what the ratchet
is for.

### R-4. The defect log is the artefact worth protecting

78 entries, each with a class and a "why it survived" analysis. Reading them
end to end, the classes concentrate:

- **Test data chosen by the implementation** appears five times, and once more
  in the consumer this session at the deployment layer. It is the single most
  productive failure mode in this codebase.
- **A rule without a gate check is a preference** appears six times.
- **A document describing behaviour, stored away from the behaviour** appears
  three times, twice this week.

That concentration is itself a measurement. **Three classes account for most
of what has gone wrong**, and all three are about the distance between a claim
and the thing that would falsify it.

### R-5. One thing I have done four times in one session

Four checks written this session asserted on the presence of a string in a
file where they meant a behaviour: `--feed` matched in a comment,
`stopPulses` matched at its definition, `traffic.setMap` matched at
construction, `relabel` matched anywhere. Each passed against a build that did
nothing. Each was caught by its own mutation and fixed.

**The mutations caught what the tests could not**, which is the argument for
the mutation harness restated in one session. It is also a specific and
correctable habit: a check that greps a file is measuring the file, and the
question is almost always about the program.

## Part 3. What is not covered by any of this

**The corpus measurements.** T36's hand-labelled sample has never been run on
western areas, which are the only kind this product is for. Everything the
package says about classification accuracy rests on twenty eastern messages
from one afternoon.

**The instrument's own blindness in the field.** T39 has a number (roughly one
poll in eight) and now a diagnostic that can explain it (T55, shipped at
0.26.0.0), and the reading has not been done.

**The staleness machine.** T54. Never observed crossing, on a page that has
been publicly reachable since 2026-08-12.

All three need a host and wall-clock time rather than an editor. **That is the
pattern in this backlog: the tasks that survive longest are the ones that
cannot be closed by typing**, and this release is another one that could.

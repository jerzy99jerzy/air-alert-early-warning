# Review of 0.32.0.0

Version: 1.0 / 2026-08-14
Baseline: `main` at 0.31.0.0, gate green. This release ships two measurement
tools, neither of which has been run against real data, one correction to a
document that had misfiled five sprints of work, and one relocation inside the
package. **No measurement in this repository changed.** Everything below is
about being able to take one.

---

## The question this release serves

The consumer's map renders almost every alert as unknown, and the reason is
structural rather than broken. `mavo/schema.py` records it: of the twenty real
messages held as fixtures, 15 carry an alert state, 4 carry a kind marker, and
**none carry both**. The kind is a separate message stream with its own
lifetime, so it can only be joined, never read off the alert. Measured over the
corpus, the join reaches 0.196 declaration coverage and 0.170 after joining;
29,400 of 42,733 alerts come out UNKNOWN.

Two candidate routes out were costed. This release builds the instrument for
each and takes neither.

## 1. `tools/unmapped_tags.py`

`data/reference/tag_map.csv` holds 127 rows built from the design window:
48,540 messages over 99 nights. The corpus is 61,041 messages over 118 days.
**Tags that first appear outside the window are absent from the map by
construction**, and `AreaTable.resolve_all` hands them back in its second
element, which its own docstring calls load-bearing precisely because ignoring
it turns a new area into silence.

The tool reads that element across the corpus and reports three things: how
many distinct tags do not resolve and how many messages they account for, how
many of those messages carry a threat-kind signal, and how the occurrences
distribute. The last one matters more than the total. A pile dominated by
singletons is typos and one-off constructions; a pile with a heavy head is
areas the map does not hold. Those need different repairs and the difference is
invisible in a sum.

**A defect in the first version of this tool, caught by running it.** Two
output lines counted messages "classified as a declaration" and "as a lift" by
calling `classify_kind_message`. That function returns nothing when the area
does not resolve, and every message in this population is one whose tag did not
resolve, so both counters were **zero by construction while reading as a
finding**. Replaced with signals read from the text directly. The lesson is the
old one: the first run of an instrument is part of building it, not a
formality after it.

## 2. `tools/api_kind_compare.py`

`api.ukrainealarm.com` returns an `alert_type` per alert, and the obvious move
is to use it to fill what the join misses. The tool exists to make that
comparison and to refuse the framing that would make it valuable and wrong.

`mavo/sources/ukrainealarm.py` opens by stating that the API, `alerts.in.ua`
and the public channel draw on one upstream. The API's `type` is therefore
**another parser over the same text, not another observation of the same
event.** Agreement between them says two readers read one message the same way
and says nothing about whether the message was right. Disagreement is the half
worth having: two readers of one text producing different labels means at least
one is wrong about something that can be read.

The tool prints the API's type vocabulary as returned, and a type it has no
row for is printed as itself rather than folded into `unknown`, because a
vocabulary gap and an absent label are different findings. Its mapping table
carries `[assumption, unverified]` on every row: each is an inference from the
string, and the API's own meaning for each value has not been read anywhere.

It also states, at the end of its own output, that one reading is a moment and
not a distribution. Nothing it prints may be quoted as a rate.

## 3. The correction

`docs/METHODOLOGY.md` attributed the artillery near-misses to **T34**. T34 is
the 321 design-window messages carrying **no tag at all**. `Загроза
артобстрілу` over `Покровська територіальна громада` carries a tag; the map
does not hold it. Different population, different cause, different repair, and
**no task in the backlog covered it** across 55 entries.

The consequence is the one that matters: the work read as scheduled for five
sprints while nothing was pointed at it. A wrong cross-reference is worse than
a missing one, because a missing one is visible as a gap.

Corrected in place with its own dated note, and **T56** opened. Its acceptance
puts the decision where it belongs: extending the map past the design window is
not mechanical, because a map built from the window is an evidence artefact and
a current map is an operational one, and the two cannot be the same file
without 99.34% and "127 distinct labels" quietly changing what they describe.
T56 also requires that if the map is extended, the old coverage figure is kept
beside the new one, because a number that moved because its denominator changed
is not an improvement.

## 4. The relocation

`read_snapshot_messages` moved from `tools/kind_coverage.py` into
`mavo/backfill.py`. The second tool needed it, `tools/` cannot become an
importable package without failing `check_single_namespace`, and a copy would
have been two readers able to disagree about what the corpus contains while
both reported confidently.

The body is unchanged. The published figures were taken with this code and are
not invalidated by its address, **but that is an argument and not a re-run**:
the corpus is tier 1 and not in the tree, so no gate here can confirm it. What
is checkable is that the next edit cannot change the reader silently, and
`tests/test_backfill_reader.py` is that: seven regressions covering
deduplication by post id, the filename filter, ordering, markup stripping, and
the refusal to invent a timestamp.

**One mutant survived the first attempt.** Replacing the timestamp guard with a
fabricated `now` passed all seven tests, because the fixture's block had no
`<time>` element and was therefore rejected by an earlier guard - the test
named "missing timestamp is dropped, not guessed" never reached the code it
named. Fixed by adding a block whose `<time>` is present and unparseable. This
is the repository's fourth recorded instance of test data chosen by the
implementation, and it is recorded rather than quietly repaired.

## What was deliberately not done

**Neither measurement was run.** Both tools need the corpus or a live key, and
neither is available to the environment that wrote them. Their output is a
measurement to be pasted into `docs/METHODOLOGY.md` by hand with its date, the
same discipline `kind_coverage` has carried since 0.16.0.0.

**No change to the map, the marker tables or the join.** P3, treating a
munition name as a declaration without a verb, is not in this release. It needs
a collision count against the near-miss pile first: `Відбій атаки
дронів-камікадзе` is the precedent for a coverage improvement that would have
turned every lift of one shape into a fresh declaration, and that trap was
found by measuring before shipping rather than after.

**No TTL change.** Coverage reads 0.196 at every window from one hour to
twenty-four. The TTL is a lever connected to nothing, and this is measured.

# Pre-push review, 0.6.0.0

The first review of this repository conducted from outside it: the 0.5.5.0 tree
was read adversarially by a reader with no memory of writing it. Twelve
findings raised, three of them defects, one in the live parse path and
undetectable by any check the repository owned.

## Findings

**F50. The page fixture encoded the parser's assumption.** The message regex
required `<time>` before the text div; the live page carries the time in the
footer, after the text. Every live-parsed event took its neighbour's timestamp,
the first text on each page was dropped, the last timestamp orphaned. The suite
could not see it because `tests/fixtures/channel.html` was written by hand in
the regex's order.

Disposition: parsing is per `data-post` block, with timestamp and text located
inside the block in either order; the fixture is a page in the live order;
harness A12 (MT13) asserts exact pairing and its mutation — widening the
timestamp search back to the whole body — turns it red.

Verified against the retrieved corpus after the fix [measured, 2026-08-09]: on
a full page the markers alternate strictly text-then-time and all twenty blocks
carry a `data-post` anchor. The footer order is the shape of the evidence, not
an assumption about the site, so the shift was systematic on every page ever
parsed live.

**F51. An interrupted write could plant a hole the census cannot see.**
Snapshots were written with a plain `write_text`. A crash mid-write leaves a
truncated page whose *filename* claims the full id range, which `--resume`
skips and `contiguity_gaps` cannot detect, because it reads ranges from names.

Disposition: write-to-scratch plus `os.replace`, scratch suffix kept out of the
`page-*.html` glob. The existing 3,034-page corpus predates the fix; its
contiguity check passed, which bounds the exposure without making the writes
retroactively atomic.

**F52. The store's ordering contract was an accident of uniform input.**
`replay` orders by ISO text, which is chronological only under one uniform
offset. Nothing enforced that: the live adapter emitted aware-UTC, the fixture
generator emitted naive datetimes, and the two had never met in one store. Had
they, replay order would have been wrong exactly where two sources correlate.

Disposition: normalize to UTC at the single point of entry and refuse naive
timestamps (`NaiveTimestamp`) rather than repairing them, since repair means
inventing an offset. The content hash spells one instant one way regardless of
reported offset, closing the second face of the same defect.

## Findings that were not defects, and what they produced

**The store keeps the old parser's rows on re-ingest.** Correct behaviour under
a hash that deliberately excludes `kind` and text, but the consequence was
nowhere written down, and it lands hard the day sprint 7 re-parses the corpus.
Recorded as D-013: a store is a parser's reading of raw evidence, rebuilt
rather than appended over, with `parser_version` named as the reopen path.

**`UrllibTransport` at 68% coverage.** The true claim that a live service
cannot be tested from here had quietly covered three pieces of local logic that
can be, one of them the size cap — a threat-model control, and by this
repository's own standard an untested control is an unmeasured one. Four tests,
no network.

**A docstring promising a degradation path that no code implemented.**
README-claim drift living one file below the lints that catch it. `is_degraded`
now exists, written by negation in the safe direction.

**Cosmetic, fixed without ceremony:** a no-op `try/except`, a hand-rolled entity
map missing numeric entities, `<br>` without the slash, two unreachable
superstring rows in the pattern tables, a stale comment in `cli.py` still
asserting the belief F44 retired, `docs/MVP.md` calling the classifier redesign
sprint 6.

## What this review says about the repository's checks

Every defect above was invisible to `make verify`, and the gate was green
throughout. That is not an indictment of the gate; it is its boundary, and the
boundary has a shape worth naming: **the checks verify internal consistency —
pins against tree, claims against code, attacks against mutations — and none of
them can verify a belief about an external system.** F50 lived precisely there,
in the one place where the repository's model of t.me/s met no evidence, and
the fixture that should have carried the evidence was written from the model.

One new check landed anyway: the defect count is now pinned across STATUS.json,
the methodology log and the README badge, because three entries arriving at
once is exactly when a hand-typed count drifts.

## Push readiness

Green: `make verify` OK, 165 tests, coverage 96.97% against the floor of 95
(the rise stays under T9's five-point threshold, so the ratchet does not move),
11 of 12 attacks mutation-verified with the twelfth printed as unverified,
docs-audit pins hold at 0.6.0.0, manual-audit clean.

Outstanding and deliberately not resolved by this review:

- **Public attribution.** `USER_AGENT` and the CI badge pin
  `github.com/jerzy99jerzy`. A public repository under that handle ties this
  work to an identity permanently and that is an operator decision, not an
  engineering one.
- **A7 remains without a mutation**, printed as unverified on every run. The
  fixture source generates rather than parses, so no single substitution
  disables a control it guards.
- **T6, T11, T20** unchanged: legal position, recipient budget, OpenSky
  registration.

# Review 0.49.0.0: the review the backlog asked for, and what it found

Version: 1.0 / 2026-08-31

Mandated as "full code review, then execute the next tasks", against the
0.48.0.1 tree. `[measured]` means executed in the container this session;
depth is stated per area rather than implied, because a review that does not
say where it looked shallowly is claiming a coverage it did not buy.

## 1. Where the review looked, and how hard

Deep, line-level with probes: `report.py` (both trailing counters, the fold),
`schema.py`, `store.py`, `cli.py` (collect paths, reconcile),
`sources/ukrainealarm_source.py`, `sources/ukrainealarm.py` (`parse_alerts`),
`kinds.py` (the join and `KindIndex`). Header-and-hazard sweep with targeted
greps over the remaining eleven modules: no bare `except`, no naive
`datetime.now()`, no mutable defaults `[measured]`. `KindIndex` keys per
`(oblast, kind)` and carries no F133-class hazard. The modules not read at
line level this session are named by omission above, deliberately.

## 2. The flagship finding: F138

The 0.48.0.0 review left one sentence armed: the trailing layer's behaviour
under multi-kind interleaving is `[unverified]`. The probe that sentence owed
came back red on the first run `[measured]`: both episode counters kept their
running state per area, so the clear of one threat kind closed an area whose
other kind still ran - 18,900 seconds missing, `open_at_as_of` extinguished,
`last_alert_ended_at` invented, on a log shaped like the two chronic areas of
2026-08-30. F133's mechanism, one layer further out than D-044 reached.
Repaired per `(area_id, kind)` in both counters, single-kind path pinned
byte-identical, five tests red-verified against the unpatched tree.

The lesson is the one the register already holds, compounding: every layer
that folds events must state its unit, and a layer that inherits the unit
silently is where the next F133 lives. Four layers found so far - source,
identity, fold, counters - each by a different session.

## 3. Two debts paid, one blindspot filed

**F135** - the API path's `unparsed` sentinel is counted, named in the recap
with the drift note, and a marked record whose region resolves is stored
under UNKNOWN rather than dropped. Paying it surfaced the adjacent blindspot:
a well-formed alert with a merely *novel type string* still folds into
UNKNOWN with no counter - filed as **T83** rather than patched here, because
a finding absorbed into an unrelated diff is a finding lost.

**F136** - a substituted stamp now marks its row (`ts_source_origin:
observed`), so E-0 can exclude by reading. The E-0 block is lifted from this
side; the measurement itself still waits on its own session.

**T77** - the precision counter no longer counts CPython interpreter tokens,
excluded by dated name rather than by shape, and six ceilings fell to their
exact new counts - the direction a ceiling is allowed to move. **T75** closed
on the 2026-08-31 host read that settled F137.

## 4. What was executed, and what deliberately was not

## 5. Errors of this session, on equal footing

Three bad `old_str` matches caught by their own asserts before writing
(recap line wrapping assumed, comment block dropped, a splice anchor
miscounted), and two test-fixture errors that reached a red run: fixtures
asserted a sentinel the parser does not emit for that shape, and used a

the source, not from the assumption. The gate held throughout; nothing wrong
was committed.

# Review 0.40.0.0: what the code does, against what the documents say it does

Version: 1.0 / 2026-08-26

Four defects, one method. **Every one was found by running a shipped function
and comparing the result against a sentence describing it** - a docstring, a
manual transcript, a task's acceptance line. None came from a failing test.
The suite was green over all four and had been for releases, which is the
finding underneath the findings: this tree's checks are strong on shape and
weak on aptness, and the gap between those two is where all four lived.

Everything labelled `[measured]` below was produced by executing the code in
this repository against constructed inputs, and the transcripts are quoted
rather than described.

## 1. The freshness of a picture rested on a stamp from the future

`staleness_s` subtracted the newest source timestamp from `as_of`; `feed_state`
compared the result against `valid_for_s`. A negative number passes that
comparison for any threshold.

`[measured]`, three stores composed through `compose()` at one `as_of`:

| Store | `state` | `observation_age_s` |
| --- | --- | --- |
| real traffic, newest row six hours old | `degraded` | 21600 |
| the same plus one row stamped one minute ahead | `ok` | -60 |
| dead seven days plus one row stamped a year ahead | `ok` | -31536000 |

The third also published `source_last_message_at` in 2027 and an **empty**
`events` block, because `event_window` has excluded stamps after `as_of` since
it was written. So one row was simultaneously not yet real and the reason the
feed called itself fresh, two readings a few lines apart in one file.

**The interesting part is not the arithmetic, it is the neighbour.**
`trailing_counts` clamps `ts_source` against `as_of` before measuring
durations, and carries a comment saying T40 measured the two clocks disagreeing
in both directions. The hazard was known, written down, and handled in the
module that counts seconds - and not in the module that decides whether the
picture may be trusted at all. Neither module knew about the other.

The realistic trigger is not a hostile channel. It is a backward drift of our
own host clock, which puts every event in the future at once and makes
`degraded` unreachable while the collector is dead. **T54 - observe the
staleness machine crossing once on a real host - is tier 1 and open.** The one
instrument that would have met this has never been run.

## 2. The corpus was read as a text the classifier never sees

`[measured]`, one message through both readers:

```
corpus reader : '&#33; Відбій тривоги в #Кам&#39;янець-Подільський_район'
live reader   : "! Відбій\nтривоги в #Кам'янець-Подільський_район"
state         : CLEAR   /  None
tags          : ()      /  ("Кам'янець-Подільський_район",)
```

The corpus **over-read states**, because a marker broken by `<br>` was rejoined
with a space, and **under-read areas**, because an undecoded entity broke the
tag pattern at the apostrophe. Opposite directions, so they do not cancel;
they bias different measurements differently. Three of the 127 rows in
`tag_map.csv` carry an apostrophe `[measured]`.

`read_snapshot_messages` was moved into the package so that a second tool would
not copy it, and its docstring has claimed one reader and one answer ever
since. The move ended the duplication and left the divergence. Six loops walk
`page-*.html` in this tree; three went through `_strip` and three did not.

**This release does not correct the figures taken with the old reader. It
withdraws their support.** Naming which: the two kind-coverage figures, the
unmapped-tag pile, and the near-miss review that produced the marker table now
in `mavo/sources/telegram.py`. That last one matters most, because it is not a
report about the table, it is the evidence for it.

## 3. The manual's first run demonstrated a pipeline understanding nothing

`[measured]`: section 4.5 printed `messages=3 parsed=2 unparsed=1`. The tree
produced `messages=3 parsed=0 unparsed=3`. The transcript came from the parser
that read oblast names out of prose, deleted in sprint 7 after F23 measured
that model at zero of twenty against real content.

The fixture beside it was a page in that same dead format. **No test referenced
it**; eight modules build their own page inline. The only pointer to it was the
manual, offering it to a first-time reader as the offline smoke test.

`manual-audit` had been a gate step for nineteen releases and was green over
all of this, because it asks whether every command has a section, whether every
section declares a kind, and whether three thresholds are quoted. Shape, three
times. The one artefact nobody compared against anything was the output block,
which is the first thing a reader believes.

**A note on the repair, because it nearly repeated the class it fixes.** The
first version of the transcript check ran every command it found, including
`mavo report --store data/events`, which constructed an `EventStore` and
**created the directory in the tree it was auditing**. It would have passed on
the second run for a reason unrelated to the manual. Execution is now limited
to `mavo collect --stub`, which reads a file and writes nothing.

## 4. A measurement that has never fired on the machine that needs it

`[measured]`, three consecutive invocations against one page:

```
poll 1: messages=3 parsed=2 unparsed=1 skipped=unknown
poll 2: messages=3 parsed=2 unparsed=1 skipped=unknown
poll 3: messages=3 parsed=2 unparsed=1 skipped=unknown
```

`_last_id` lives on a source object, `_cmd_collect` builds a fresh one per
invocation, and the unit is a `oneshot` under a timer. **No two polls have ever
met in one process on the host.** T18's acceptance - consecutive polls compare
post ids - is satisfied by a class production never instantiates.

F27 records that the post id is the only thing that makes a skipped message
observable. The condition it defends against is a mass alert emitting more than
a page between polls, which is the one condition under which this project has a
purpose. It has been unmeasurable since deployment.

**Left unfixed on purpose.** The cursor must live where two invocations can
both read it, and this tree already answers that question twice, differently:
`feed_attempts` holds it for the Polish feed with a schema comment calling it a
debt owed to ourselves, and T66 records that for the Ukrainian channel the same
information lives in the log and not in the store. D-034 rests on the same
record and names T71 as its prerequisite, but T71 delivers a log line and the
publisher reads the store - `lint_domain` forbids it reading the other. **T71
as scoped does not unblock D-034**, and noticing that before the work is the
only cheap moment to notice it.

## 5. Found in the same reading, not fixed, and not given numbers here

Reserving identifiers in advance is how this release cited a decision that
already existed. These are described so the next person to open a task can read
the file and issue a number then.

- **The publish loop replays the entire log every cycle.** `[measured]` at
  300,000 rows: 3 s per cycle and 114 MB resident, growing linearly, with no
  retention anywhere. `idx_events_ts_source` exists and no query has a `WHERE`
  clause that could use it. The trap: the per-area fold is over all time by
  construction, so the window cannot simply be narrowed without a materialised
  current-state view - which is the same object section 6 needs.
- **An alert episode has no expiry and a kind declaration does.** `[measured]`
  an ACTIVE from 300 days ago still publishes as `active`. `mavo/kinds.py`
  solved the identical failure and wrote down why. Opened as T81.
- **`areas_with_border_distance` counts rows in a file, not areas the system
  can serve.** `[measured]` 126 areas resolve and 126 carry a distance; the
  file holds 127 and one code is reachable from no tag. Two denominators, one
  number, which is T49's class.
- **The provenance note in `STATUS.json` is wider than the truth.** It says the
  measured figures come from `make verify` and `mavo policy`, with three named
  exceptions. The corpus figures come from tools the gate does not run, against
  a corpus not in the tree, so the gate could not produce them if it tried.
- **`mavo/rules.py` imports from `mavo/sources/fixture.py`.** The rule type is
  the fixture's type, and no adapter turns the store into it, so the decision
  layer is structurally bound to synthetic input. `EAST_TO_WEST` orders six
  oblasts of twenty-three by hand, while measured centroid distances to the
  border sit in `data/reference/border_km.csv`.
- **Two definitions of west.** `[measured]` `areas.WESTERN_OBLASTS` covers eight
  oblasts and 36 areas; `schema.BORDER_OBLASTS | SECOND_RING_OBLASTS` covers
  six. The contract flag uses one, the rules use the other, and nothing records
  the difference as deliberate.
- **A redirect can escape the transport deadline.** The scheme check binds the
  initial URL; the default opener still carries handlers that would follow a
  redirect outside the bounded connection classes. Low probability, three lines
  to close, and the module claims to be the single seam to the internet.

## 6. What this release does not let anyone conclude

The gate is green on synthetic and fixture input. It does not say the channel
still serves the shapes the patterns expect, it does not say 120 s is the right
skew tolerance, and it says nothing about the figures section 2 withdrew. Three
of the four defects were found by reading the machine against a document, and
that remains the only method here with a record of working.

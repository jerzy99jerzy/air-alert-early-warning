# MANUAL

Operator's manual for MAVO. Written from the first sprint rather than at the end,
because a manual written afterwards documents what was built instead of what was
promised, and the gap between the two is the interesting part.

**How to read the status markers.** Every section carries one:

- **BUILT** works today, in this release, and is covered by tests.
- **PARTIAL** exists but is incomplete in a way named in the section.
- **NOT BUILT** does not exist. The sprint that will build it is named. Nothing in
  a NOT BUILT section describes present behaviour, and none of it should be
  relied on.
- **NARRATIVE** describes no behaviour at all. Framing and orientation only.

`tests/lint_domain.py` fails if a CLI subcommand exists with no section here, so
this document cannot silently fall behind the tool.

---

## 1. What this tool is for — NARRATIVE

MAVO watches air-alert state in the western oblasts of Ukraine and asks one
question: does a given pattern of alerts carry enough information to justify
interrupting a person in Poland.

The honest default answer is no. Massed strike campaigns against western Ukraine
cover roughly 57% of days, so a rule that fires on campaign nights has near-perfect
recall and almost no specificity. Most of this tool exists to measure that, and to
refuse to raise an alarm when the measurement does not support one.

**What it is not.** Not a substitute for sirens or the state alerting system. It
reads a feed from before the border, which puts it one step earlier in the chain
and correspondingly less certain. If your only warning comes from here, you have
misconfigured your life, not the tool.

## 2. Installation — BUILT

Requires Python 3.11 or newer. No runtime dependencies.

```
git clone <repository>
cd air-alert-early-warning
pip install -e ".[dev]"
```

Verify the install:

```
mavo --version
make verify
```

`make verify` is the only gate. It runs the test suite with a coverage floor,
`ruff`, `mypy --strict`, and four repository lints. If it is not green, nothing
below is trustworthy.

## 3. First run, with no credentials — BUILT

Every command works offline against a generated history. This is deliberate: a
person evaluating the tool should not have to obtain an API token first.

```
mavo fixture --out data/raw/fixture.sqlite --weeks 52
```

Output:

```
nights=364 events_added=1152 crossings=4
store=data/raw/fixture.sqlite total_events=1152
```

`crossings` is the number of nights that ended in a border violation. Four in a
year is roughly the real-world rate, and it is the reason nothing here can be
validated quickly: the positive class is tiny.

**Nothing generated by this command is evidence about the world.** It exercises
the machinery. A number printed from it describes the generator.

## 4. Commands — NARRATIVE

### 4.1 `mavo fixture` — BUILT

Generates a synthetic history and writes it to an event store.

| Option | Default | Meaning |
| --- | --- | --- |
| `--out` | `data/raw/fixture.sqlite` | Store path. Created if absent |
| `--weeks` | `52` | Length of the generated history |
| `--seed` | `1968` | Deterministic seed. The same seed always produces the same history |

The store is append-only and idempotent by content hash, so running the command
twice against the same path adds nothing the second time.

Scenarios in the generated mix, with their share:

| Scenario | Share | What it represents |
| --- | --- | --- |
| `quiet` | 34% | Nothing happening |
| `campaign-no-crossing` | 55% | A massed campaign that does not reach Poland. **The decisive world**: every alarm here is a false positive |
| `clean-missile` | 0.5% | A missile campaign ending in a crossing |
| `clean-drone` | 0.5% | A drone wave ending in a crossing |
| `degraded-feed` | 5% | A source goes silent. States become `UNKNOWN` and must not read as all-clear |
| `poisoned-feed` | 2% | A source claims the whole country is alight at once |
| `border-only` | 3% | Wrong vector: the far south-west alone |

### 4.2 `mavo gate` — BUILT

Scores each candidate rule individually against the base rate.

| Option | Default | Meaning |
| --- | --- | --- |
| `--weeks` | `208` | Length of the history to score against |
| `--seed` | `1968` | Deterministic seed |

Reading the output. A line looks like:

```
R3-border-missile: precision=0.054 recall=0.467 lift=5.227 p=0.0001 alarms/week=0.625 [reported]
  [FAIL] R3-border-missile: recall 0.47 below floor 0.9; alarm rate 0.62/week within budget 2.00/week; association p=0.000
```

| Field | Meaning | How to read it |
| --- | --- | --- |
| `precision` | P(crossing given the rule fired) | Expect a low number. 0.054 means about one alarm in nineteen precedes a crossing |
| `recall` | P(rule fired given a crossing) | Below 0.9 the rule misses events and fails outright |
| `lift` | precision divided by the base rate | Near 1.0 means the rule told you nothing a calendar would not have |
| `p` | one-sided Fisher exact | Above 0.05 the association is indistinguishable from chance |
| `alarms/week` | firing rate | The number that decides whether a rule is usable, not precision |
| `[reported]` | provenance | The weakest label among the rule's inputs. `measured` would mean observed directly, `reported` means a source said so |
| `unknown` | any metric | Genuinely unknown, printed as such. It never means zero |

The gate has three conditions and failing any one is decisive: recall at least
0.90, alarm rate at most the allocated budget, association p at most 0.05.

### 4.3 `mavo policy` — BUILT

Scores the regime-split decision policy: one rule per timing regime, sharing one
attention budget.

| Option | Default | Meaning |
| --- | --- | --- |
| `--weeks` | `208` | History length |
| `--seed` | `1968` | Deterministic seed |
| `--allocation` | `equal` | `equal` divides the budget evenly. `demand` allocates by measured firing rate plus 25% headroom |

Why two regimes. A missile crossing from an alert in Lviv oblast is roughly six
minutes; a drone crossing from Volyn is roughly thirty-three. One threshold
cannot serve both, and sprint 2 proved it the expensive way: a global recall of
0.47 turned out to be 7 of 7 on missile nights and 0 of 8 on drone nights.

**`--allocation demand` is expected to fail, and that is the result.** Measured
demand is 2.46 alarms per week against a total of 2.00, so the allocator refuses
to build the policy. It exits 1 and prints why. It does not trim a share to make
the sum fit, because a policy that passes its own gate while overrunning the
recipient is worse than one that refuses to exist.

Reading a `COVERAGE GAP` line. If it appears, a crossing kind is served by no
regime at all, and the recall printed above it is scoped to the regimes that are
served. It says nothing about the crossings in the gap. Treat a policy with a
coverage gap as a policy with a hole, not as a policy with good numbers.

### 4.4 `mavo collect` — PARTIAL

Polls the public Telegram channel once and reports what it understood. It does
not yet write to the store; that lands with continuous collection in sprint 5.

| Option | Default | Meaning |
| --- | --- | --- |
| `--stub` | none | Read a saved page from disk instead of the network. Use this to test the pattern table offline |
| `--save-raw` | none | Write the fetched page verbatim into this directory before parsing, as `channel-<UTC timestamp>.html`. This is how the sprint-5 corpus is built (T19): the page is a ~20-message window (F27), so content not saved now is gone. Point it at `data/raw/`, which is git-ignored |

```
mavo collect --stub tests/fixtures/channel.html
messages=3 parsed=2 unparsed=1 latency=0.001s
```

**`unparsed` is the number to watch.** Messages that match no pattern are counted
and printed, never dropped. A rising count means the pattern table is drifting
from the channel's actual wording, which would otherwise show up as a channel
that has gone quiet.

**Measured, and it failed.** On 2026-08-08 the shipped pattern table was run
against twenty real messages from the channel. It classified **none of them**.
The state markers were correct (15 of 20), the means markers partly correct (4 of
20), and the area table matched nothing at all, because the channel names raions
and hromadas while the table was keyed on oblasts.

So this command currently reports `parsed=0` against live content, and that is
the honest state rather than a bug to be surprised by. The redesign is sprint 5;
see F23 to F27 in `docs/METHODOLOGY.md`. Until then, `--stub` against the bundled
fixture is the only path that parses anything.

Exit codes:

| Code | Meaning |
| --- | --- |
| 0 | fetched and parsed, whatever the unparsed count |
| 3 | the source was unreachable. Distinct from reachable and quiet |
| 4 | `--save-raw` was requested and the snapshot could not be written. Loud rather than silent, because a snapshot that quietly fails to land is a quiet loss of exactly the evidence the redesign needs |

### 4.5 `mavo watch` — NOT BUILT (sprint 6)

Will run the decision policy continuously and emit to an output channel. Until
shadow mode has run its full window, this command will refuse to send anything.

## 5. Interpreting an alarm — NOT BUILT (sprint 6)

This section is deliberately empty. No alarm has ever been produced by this tool,
no threshold has been calibrated against real data, and writing guidance for a
message that does not exist would be describing a product rather than documenting
one.

What can be said now: when it exists, an alarm will carry the rule that fired, the
time it fired, the measured historical worth of that rule, and a statement that it
does not replace official warning. It will never carry a probability of impact,
because nothing in this design can compute one.

## 6. Operational limits — BUILT where noted

**Rate limits.** alerts.in.ua: roughly 8 to 10 requests per minute soft, 12 hard,
with the history endpoint separately limited to 2 per minute. Polling at 30-second
intervals sits at 2 per minute, well inside both. Do not use the history endpoint
in real time.

**Token handling.** Tokens live in the system keychain, never in the tree, never
in a client. The `.gitignore` covers the store and the raw data tier from the
first commit.

**Source independence, or the absence of it.** alerts.in.ua and
api.ukrainealarm.com both draw on the same upstream Telegram channel. Running both
protects against a transport failure in one, and does **not** protect against a
wrong or silent upstream. Do not read a two-source agreement as confirmation. This
is why the ADS-B channel matters: it is the only planned input that observes
independently.

**Feed latency.** The store records both the source timestamp and the ingest
timestamp because the difference consumes the warning budget directly. In the
missile regime the whole budget is about six minutes, so a feed that publishes
three minutes late halves the product.

## 7. Troubleshooting — PARTIAL

| Symptom | Cause | Action |
| --- | --- | --- |
| `make verify` fails on coverage | New code without tests | Write the test. The floor is a ratchet and is not lowered |
| `lint-limitations` fails | A README claim no longer matches the tree | Fix the tree or delete the claim. Do not add an exemption |
| `mavo policy --allocation demand` exits 1 | Measured demand exceeds the total budget | This is the designed answer, not a fault. Demote a regime |
| Store grows on every poll | Content hash changed | Check that `ts_ingest` is still excluded from the hash |
| A metric prints `unknown` | The quantity is genuinely undefined | Do not substitute zero. Find out why it is undefined |

Sections for live-collection failures will be written when live collection exists.

## 8. Reporting a problem — NARRATIVE

`SECURITY.md` defines what counts as a security defect here: a suppression that
can be walked through, a path where `UNKNOWN` behaves as `CLEAR`, or a
documentation claim the tree does not implement. Include the input that
demonstrates it. A probe is worth more than a reading.
